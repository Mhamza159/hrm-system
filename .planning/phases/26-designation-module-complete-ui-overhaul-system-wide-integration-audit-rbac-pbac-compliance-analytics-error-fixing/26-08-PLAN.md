## 2. Step-by-Step Implementation

### Step 1: Cross-Module Integration Audit & Safeguards
1. **Employees Module (`employee.service.js`)**:
   - Audit `createEmployee`: When assigning `designationId`, ensure the designation exists AND is not archived (`isArchived !== true`).
   - Audit `updateEmployee`: If `designationId` changes or is updated, verify the new designation is not archived.
   - Audit `recordPromotionHistory`: When an employee receives a promotion, verify the destination designation is active (`isArchived: false`).
2. **Recruitment & Job Postings**:
   - Verify that when job openings or requisitions are drafted, designation selectors filter out archived designations.
3. **Performance & KPI Templates**:
   - Ensure appraisal and KPI templates linked to designations handle active designations properly without breaking on legacy/archived records.
4. **Organization Hierarchy / Org Chart**:
   - Ensure employee cards in the Org Chart render the designation title and grade tier cleanly, handling any historical or missing designation gracefully without UI exceptions.

### Step 2: Implement Comprehensive Vitest Test Suite (`backend/tests/designations.overhaul.e2e.test.js`)
Develop an end-to-end integration test suite using MongoDB Memory Server / Test DB:
1. **Authentication & RBAC Setup**:
   - Seed test users: Super Admin (`org.manage`, `org.view`), HR Manager (`org.manage`, `org.view`), Employee (`org.view` only), and Unauthenticated user.
   - Seed active department.
2. **Designation CRUD & Code Uniqueness**:
   - Test creating designation with valid grade tier (`Junior`, `Mid`, `Senior`, `Lead`, `Executive`).
   - Test duplicate code rejection within the same department.
   - Test updating designation title, grade tier, and department.
3. **KPI Statistics & Analytics Aggregations**:
   - Test `GET /api/v1/designations/stats` returns accurate 7 KPI metrics (`totalDesignations`, `activeDesignations`, `archivedDesignations`, `totalAssignedStaff`, `staffedDesignations`, `emptyDesignations`, `departmentsRepresented`).
   - Test `GET /api/v1/designations/analytics` returns grade distribution and department breakdown.
4. **Single Designation Inspection with Assigned Staff**:
   - Assign test employees to a designation.
   - Test `GET /api/v1/designations/:id` returns enriched designation data with `assignedEmployees` array containing avatar, name, code, email, status.
5. **Archival Lifecycle & Invariants**:
   - Test `PATCH /api/v1/designations/:id/archive` sets `isArchived: true`, `archivedAt`, and `archivedBy`.
   - Verify archived designation is excluded from `GET /api/v1/designations` (active directory).
   - Verify archived designation appears in `GET /api/v1/designations/archived`.
   - Test `createEmployee` with an archived designation returns 400 Bad Request.
6. **Mandatory Employee Assignment Restriction Guard**:
   - Attempt `DELETE /api/v1/designations/:id/permanent` on an archived designation that still has $\ge 1$ assigned employee.
   - Assert response status is `400 Bad Request`.
   - Assert error message contains: *"This designation cannot be permanently deleted because 1 employee(s) are still assigned to it. Please reassign all employees to another designation before proceeding."*
   - Verify designation record remains in the database.
7. **Reassignment and Successful Permanent Deletion**:
   - Reassign or remove employee from the designation.
   - Attempt `DELETE /api/v1/designations/:id/permanent`.
   - Assert response status is `200 OK` and designation is purged from the database.
8. **Restoration Lifecycle**:
   - Archive a designation.
   - Test `PATCH /api/v1/designations/:id/restore` resets `isArchived: false`, `archivedAt: null`, `archivedBy: null`.
   - Verify designation returns to `GET /api/v1/designations`.
9. **RBAC Permission Gate Enforcement**:
   - Verify unauthenticated requests return 401.
   - Verify user without `org.manage` attempting archive/restore/delete returns 403 Forbidden.
