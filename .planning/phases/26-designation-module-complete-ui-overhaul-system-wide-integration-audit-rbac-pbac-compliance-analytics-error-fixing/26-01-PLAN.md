## 2. Step-by-Step Implementation

### Step 1: Update `designation.model.js`
- Add archival tracking fields:
  ```javascript
  isArchived: {
    type: Boolean,
    default: false,
    index: true
  },
  archivedAt: {
    type: Date,
    default: null
  },
  archivedBy: {
    type: mongoose.Schema.Types.ObjectId,
    ref: 'User',
    default: null
  }
  ```
- Add compound indexes:
  ```javascript
  designationSchema.index({ isArchived: 1, isDeleted: 1 });
  designationSchema.index({ departmentId: 1, isArchived: 1 });
  designationSchema.index({ code: 1, departmentId: 1, isArchived: 1 });
  ```

### Step 2: Implement Archival Lifecycle in `department.service.js`
- **`getAllDesignations`**:
  - Update query to `{ isDeleted: false, isArchived: { $ne: true } }` by default to remain 100% backwards-compatible with unmigrated Atlas documents.
  - Idempotent background normalization: `Designation.updateMany({ isArchived: { $exists: false } }, { $set: { isArchived: false } }).catch(() => {});`
- **`getArchivedDesignations({ search, departmentId, grade, page, limit, sortBy, sortOrder })`**:
  - Query `{ isArchived: true, isDeleted: false }`.
  - Populate `departmentId` (`name code`) and `archivedBy` (`name email`).
  - Attach active headcount via `Employee.aggregate`.
  - Return paginated `{ docs, total, page, limit, totalPages }`.
- **`archiveDesignation(id, actor)`**:
  - Verify designation exists and is not already archived.
  - Set `isArchived: true`, `archivedAt: new Date()`, `archivedBy: actor._id`.
  - Audit log: action `designation.archive`.
- **`restoreDesignation(id, actor)`**:
  - Verify designation is currently archived.
  - Check code uniqueness within target department: prevent restore if active designation in same department already has the same code.
  - If associated `departmentId` is deleted or archived, verify and alert or handle cleanly.
  - Set `isArchived: false`, `archivedAt: null`, `archivedBy: null`, `isActive: true`.
  - Audit log: action `designation.restore`.
- **`permanentDeleteDesignation(id, actor)`**:
  - **CRITICAL RESTRICTION RULE**: Count assigned employees:
    ```javascript
    const assignedCount = await Employee.countDocuments({ designationId: id });
    if (assignedCount > 0) {
      throw new ApiError(
        400,
        `This designation cannot be permanently deleted because ${assignedCount} employee(s) are still assigned to it. Please reassign all employees to another designation before proceeding.`
      );
    }
    ```
  - Purge with `Designation.deleteOne({ _id: id })`.
  - Audit log: action `designation.permanent_delete`.

### Step 3: Implement Cross-Module Assignment Guard in `employee.service.js`
- In `createEmployee`:
  - When `payload.designationId` is provided:
    ```javascript
    const desig = await Designation.findOne({ _id: payload.designationId, isDeleted: false });
    if (!desig) throw new ApiError(404, 'Specified designation does not exist');
    if (desig.isArchived) throw new ApiError(400, `Cannot assign employee to designation '${desig.title}' because it is archived.`);
    ```
- In `updateEmployee`:
  - When `payload.designationId` changes: verify existence and block if `desig.isArchived`.
- In `recordPromotionHistory`:
  - When `payload.newDesignationId` is provided: verify existence and block if `desig.isArchived`.

### Step 4: Register Controller & Routes in `designation.routes.js`
- `GET /archived` -> `departmentController.getArchivedDesignations` (`checkPermission('org.view')`)
- `PATCH /:id/archive` -> `departmentController.archiveDesignation` (`checkPermission('org.manage')`)
- `PATCH /:id/restore` -> `departmentController.restoreDesignation` (`checkPermission('org.manage')`)
- `DELETE /:id/permanent` -> `departmentController.permanentDeleteDesignation` (`checkPermission('org.manage')`)
- Route ordering invariant: mount `/archived` BEFORE `/:id`.
