# Plan 31-02: Audit Analytics, Aggregation Pipelines & Statistics Backend APIs

## Objective
Author backend analytics and summary calculation endpoints for the Audit Log module. Provide real-time, database-driven metrics and aggregation pipelines for total events, daily/weekly/monthly activity velocity, successful vs failed operations, security events, critical administrative actions, module distribution, and hourly/daily activity trends.

## Tasks
1. **Query & Validation Enhancement (`backend/src/modules/audit/audit.validation.js`)**:
   - Update `auditQuerySchema` to support filtering by:
     - `status`: `'SUCCESS' | 'FAILURE'`.
     - `severity`: `'LOW' | 'MEDIUM' | 'HIGH' | 'CRITICAL'`.
     - `category`: `'AUTHENTICATION' | 'DATA_CHANGE' | 'SECURITY' | 'ADMINISTRATIVE' | 'SYSTEM'`.
     - `actorRole`: string.
     - `isArchived`: boolean string coercion.
   - Define `auditStatsQuerySchema` and `auditAnalyticsQuerySchema` supporting `timeRange` (`24h`, `7d`, `30d`, `90d`, `custom`) and optional `module` scoping.

2. **Domain Service Analytics Pipelines (`backend/src/modules/audit/audit.service.js`)**:
   - Implement `getAuditStats(filters)`:
     - Total events count.
     - Today's events count (since 00:00:00 UTC).
     - This week's events count (last 7 days).
     - This month's events count (last 30 days).
     - Total successful vs failed activities count and success rate percentage.
     - Security events count (`category: 'SECURITY'`).
     - Administrative activities count (`category: 'ADMINISTRATIVE'`).
     - Critical activities count (`severity: 'CRITICAL'` or `'HIGH'`).
     - Unique active actors count (`$addToSet: '$actorEmail'`).
   - Implement `getAuditAnalytics(filters)`:
     - `timeline`: Grouped by hour (for 24h) or by day (for 7d/30d), counting total, success, and failure.
     - `moduleDistribution`: Breakdown of event count per module.
     - `actionDistribution`: Top 10 most frequent actions.
     - `categoryDistribution`: Event counts per category.
     - `severityDistribution`: Event counts per severity level.
     - `securityTrends`: Specific counts for `LOGIN_FAILED`, `ACCOUNT_LOCKED`, `PERMISSION_CHANGED`, `UNAUTHORIZED_ACCESS`.

3. **Controller & Route Integration (`audit.controller.js` & `audit.routes.js`)**:
   - Add `GET /api/v1/audit-logs/stats` with `checkPermission('audit.view', 'all')`.
   - Add `GET /api/v1/audit-logs/analytics` with `checkPermission('audit.view', 'all')`.
   - Ensure all responses adhere to standard envelope `{ success: true, data: { ... }, message: "..." }`.

## Verification Criteria
- `GET /api/v1/audit-logs/stats` returns accurate counts calculated directly from MongoDB.
- `GET /api/v1/audit-logs/analytics` produces aggregated trend series matching date boundaries without zero-padding holes.
- Endpoints respond in under 150ms using compound indexes.
