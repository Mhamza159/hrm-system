# Plan 31-01: Enhanced Audit Log Data Model, Enriched Logging Engine & Cross-Module Event Attribution

## Objective
Upgrade the core Audit Log architecture to an enterprise forensic ledger. Enhance `AuditLog` Mongoose schema with status, severity, category, description, and client device tracking. Enrich `AuditService` and `recordAuditLog` with intelligent user agent parsing, robust field sanitization (redacting passwords, tokens, raw secrets), and audit cross-module event generation across Authentication, Roles, Employees, Departments, Shifts, Attendance, Leaves, and Payroll.

## Tasks
1. **AuditLog Schema Enhancement (`backend/src/models/auditLog.model.js`)**:
   - Add `status`: enum `['SUCCESS', 'FAILURE']`, default `'SUCCESS'`, indexed.
   - Add `severity`: enum `['LOW', 'MEDIUM', 'HIGH', 'CRITICAL']`, default `'LOW'`, indexed.
   - Add `category`: enum `['AUTHENTICATION', 'DATA_CHANGE', 'SECURITY', 'ADMINISTRATIVE', 'SYSTEM']`, default `'DATA_CHANGE'`, indexed.
   - Add `description`: String (concise, human-readable activity synopsis).
   - Add `device`: subdocument `{ browser: String, os: String, deviceType: String }`.
   - Add `isArchived`: Boolean (default `false`, indexed), `archivedAt`: Date (default `null`).
   - Add compound indexes: `{ category: 1, createdAt: -1 }`, `{ severity: 1, createdAt: -1 }`, `{ status: 1, createdAt: -1 }`, `{ isArchived: 1, createdAt: -1 }`.

2. **Centralized Audit Engine & Sanitization (`backend/src/services/audit.service.js`)**:
   - Implement `parseUserAgent(uaString)` helper to extract browser (Chrome, Firefox, Safari, Edge), OS (Windows, macOS, Linux, iOS, Android), and device type (Desktop, Mobile, Tablet).
   - Implement `sanitizeAuditPayload(obj)` to deep-clone and mask sensitive keys (`password`, `passwordHash`, `token`, `refreshToken`, `authorization`, `cnic`, `accountNumber`, `secretKey`, `apiKey`).
   - Enhance `AuditService.log` and `recordAuditLog` to accept and persist `status`, `severity`, `category`, `description`, auto-filling defaults based on action semantics.
   - Guarantee failure-safe logging: audit write errors log to stderr and never abort parent business transactions.

3. **Cross-Module Audit Event Attribution Audit**:
   - Verify and calibrate event emissions across key services:
     - `auth.service.js`: `USER_LOGIN` (SUCCESS), `LOGIN_FAILED` (FAILURE, HIGH severity, SECURITY category), `USER_LOGOUT`, `PASSWORD_RESET`, `ACCOUNT_LOCKED` (CRITICAL severity, SECURITY category).
     - `role.service.js`: `ROLE_CREATED`, `ROLE_UPDATED`, `ROLE_DELETED` (HIGH severity, ADMINISTRATIVE category), with granular permission diffs.
     - `employee.service.js`: `EMPLOYEE_CREATED`, `EMPLOYEE_UPDATED`, `EMPLOYEE_STATUS_CHANGED`, `EMPLOYEE_ARCHIVED`.
     - `payroll.service.js`: `PAYROLL_GENERATED`, `PAYROLL_APPROVED`, `PAYROLL_STATUS_CHANGED` (HIGH severity, ADMINISTRATIVE category).
     - `attendance.service.js` & `leave.service.js`: `ATTENDANCE_OVERRIDE`, `LEAVE_APPROVED`, `LEAVE_REJECTED`.

## Verification Criteria
- `AuditLog` records persist with validated status, severity, category, description, and device metadata.
- Passwords and sensitive auth tokens never appear in before/after diffs or metadata.
- System operations and background cron tasks record with `actorRole: 'SYSTEM'`.
- Database compound indexes verify query optimization for multi-filter lookups.
