# Plan 31-03: Audit Export Engine, Retention Policies & Forensic Compliance APIs

## Objective
Implement enterprise compliance reporting and data retention capabilities for system audit logs. Author server-side streaming export endpoints (CSV and Excel formats) that respect active filters, redact sensitive data, and enforce PBAC scoping. Establish immutable retention policy checks and guarded soft-archival endpoints that protect historical audit evidence from tampering or unauthorized destruction.

## Tasks
1. **Export Engine Implementation (`backend/src/modules/audit/audit.service.js`)**:
   - Implement `exportAuditLogs(filters, format = 'csv')`:
     - Query matching records with a maximum safety cap of 10,000 rows.
     - Transform records into clean tabular rows: `Timestamp (UTC)`, `Timestamp (PKT)`, `Event ID`, `Actor Email`, `Actor Role`, `Action`, `Module`, `Target Model`, `Target ID`, `Category`, `Severity`, `Status`, `Description`, `IP Address`, `Browser`, `OS`.
     - Generate standard CSV string or Excel buffer.
     - Ensure stream-friendly or chunked processing to prevent heap memory exhaustion.
   - Record an internal audit event when export is triggered: `AUDIT_LOGS_EXPORTED` with actor details and filter criteria.

2. **Retention & Archival Management APIs**:
   - Implement `getRetentionSummary()`:
     - Return total active records count, total archived records count, oldest record timestamp, newest record timestamp, and configured retention policy window (e.g. 365-day statutory compliance standard).
   - Implement `archiveAuditLogs({ olderThanDays })`:
     - Guarded endpoint allowing authorized Super Admin to flag records as `isArchived: true` and set `archivedAt: new Date()` without deleting them.
     - Permanent purge is strictly forbidden through application APIs to protect forensic integrity.

3. **Controller & Route Integration (`audit.controller.js` & `audit.routes.js`)**:
   - Define `GET /api/v1/audit-logs/export` with `checkPermission('audit.export', 'all')`.
     - Supports query parameters `format=csv` or `format=excel`, plus all search and filter params.
     - Sets appropriate HTTP headers: `Content-Disposition: attachment; filename="audit-logs-export-[timestamp].[csv|xlsx]"`.
   - Define `GET /api/v1/audit-logs/retention` with `checkPermission('audit.view', 'all')`.
   - Define `POST /api/v1/audit-logs/archive` with `checkPermission('audit.view', 'all')` (restricted to Super Admin role).

## Verification Criteria
- Exporting audit logs produces well-formatted CSV/Excel files with PKT timezones and sanitized fields.
- Triggering export creates an audit entry in the database.
- Retention summary returns verified count metrics.
- Hard delete/purge operations remain impossible via public API endpoints.
