# Plan 10-02: Granular Skills Tokenizer & Matched vs Unmatched Evaluation

## Objective
Fix the inverted skills matching defect in `ai.service.js:screenCandidateFit`. Tokenize multi-skill job requirement strings into distinct individual skills, perform exact bidirectional skill comparison, and clearly delineate `matchingStrengths` from `missingSkills`.

## Proposed Changes
1. **`backend/src/services/ai.service.js`**:
   - Implement `tokenizeJobRequirements(requirements = [])`:
     - Identifies compound requirement strings (e.g. `'React Js'`, `'Node Js Html Css Javascript Mongo DB MYSQL Tailwind Css Bootstrap'`).
     - Splits on delimiters (`,`, `;`, `\n`, `|`) and expands known tech skill keywords into distinct individual requirement tokens.
     - Removes duplicate or overlapping tokens.
   - Upgrade `screenCandidateFit`:
     - Compare candidate parsed skills against tokenized individual requirements.
     - Mark matched skills with exact normalized string boundaries (e.g., `'React'` matches `'React Js'` or `'React.js'`, but `'css'` will NOT match `'node js'`).
     - Explicitly populate `matchingStrengths` with matched skills and `missingSkills` with unmatched job requirements.
     - Recalculate match score dynamically based on the ratio of verified matched skills to required skills and candidate experience.
2. **AI Screening Prompt Hardening**:
   - Update `systemPrompt` in `screenCandidateFit`:
     - *"Strictly list only skills found in both candidate CV and job requirements under matchingStrengths. List any job requirement not found in candidate CV under missingSkills. Do not combine or assume missing skills."*
3. **Unit Tests**:
   - Create `backend/tests/m15.skillsMatching.test.js`:
     - Test compound requirement string splitting (`'Node Js Html Css Javascript Mongo DB'`).
     - Verify candidate with React and CSS has `matchingStrengths: ['React', 'CSS']` and `missingSkills: ['Node.js', 'MongoDB', 'JavaScript']`.
     - Verify match scores reflect accurate skills coverage.
