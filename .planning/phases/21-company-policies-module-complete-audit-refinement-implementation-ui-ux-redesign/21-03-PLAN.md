Implement the core governance workflows of the **Company Policies Module**: the detailed inspection drawer/reading view, immutable version history timeline with previous version inspection, manager review and approval interface (with approve/reject notes), and publishing workflow modal with effective-date scheduling and workforce notifications.

## 3. Detailed Tasks

### Task 1: Policy Detail Drawer & Reader (`PolicyDetailDrawer.jsx`)
- Wide slide-over sheet or modal (`max-w-3xl` / `w-[750px]`):
  - **Header**:
    - Policy title, policy code (`POL-SEC-002`), category badge, version indicator (`v2.1 · Active Version`).
    - Status pill with pulsing live indicator.
    - Quick actions: "Version History", "Print / PDF", "Edit" (if permitted), and Close button.
  - **Metadata Summary Bar**:
    - Effective Date, Review Cycle, Owner Department, Target Scope (`All Staff` / `Engineering Only`).
    - Acknowledgement mandate: "Mandatory Signature Required · 7 days grace period".
  - **Structured Policy Reader**:
    - Clean editorial typography adhering to DESIGN.md.
    - Render formatted policy articles, clauses, code of conduct, and obligations.
    - Attached Documents Card: If PDF/DOCX attached, displays file icon, name, size, and secure "Download Document" button using signed streaming.
  - **Governance & Audit Trail Box**:
    - Authored by, Reviewed by, Approved by, Published on timestamps.

### Task 2: Immutable Version History Timeline (`PolicyVersionHistoryModal.jsx`)
- Interactive audit timeline of past revisions:
  - Fetches `/api/v1/policies/:id/versions`.
  - Displays chronological list of versions (`v1.0`, `v1.1`, `v2.0`):
    - Version number and badge (`Active Version` vs `Superseded`).
    - Change summary explaining what was amended and why.
    - Published date and author name.
    - "Inspect This Version" action: Allows reading the exact immutable snapshot of that historical version without mutating the active version.
    - Acknowledgement count associated with that specific version.

### Task 3: Policy Review & Approval Workflow (`PolicyApprovalModal.jsx`)
- Interface for authorized approvers (`policy.approve`):
  - Triggered when a policy in `Pending Approval` status is inspected.
  - Displays:
    - Policy draft metadata and proposed changes.
    - Approver comment box for guidance or remarks.
  - Two primary actions:
    - **Approve**: Advances policy status to `Approved` (ready for publishing).
    - **Reject**: Requires a mandatory `rejectionReason` textarea explaining why the policy draft was rejected; sets status to `Rejected` and notifies author.

### Task 4: Policy Publishing Workflow Modal (`PublishPolicyModal.jsx`)
- Final deployment gate for approved policies (`policy.publish`):
  - Verify effective date (immediate vs scheduled future date).
  - Acknowledgement settings verification:
    - Confirm whether all eligible employees must acknowledge this version.
    - Notify author if employees who acknowledged previous versions need to re-sign.
  - Multi-channel notification prompt: "Send in-app notification & alert to all 48 eligible employees".
  - One-click "Publish Policy Now" execution with optimistic state update and success toast.
