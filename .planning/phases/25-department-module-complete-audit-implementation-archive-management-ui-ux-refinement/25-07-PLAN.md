# Plan 25-07: Comprehensive End-to-End Vitest Test Suite & Quality Verification

**Phase**: 25 · Department Module — Complete UI Overhaul, Functional Audit, Analytics, RBAC/PBAC Compliance & Error Fixing  
**Plan ID**: 25-07  
**Goal**: Author and verify an exhaustive Vitest test suite (`backend/tests/departments.overhaul.e2e.test.js`) verifying analytics aggregation, searchable candidate queries with complete employee profiles, archive, restore, and employee deletion blocking, followed by frontend linting and production build verification.

---

## 1. Test Suite Coverage (Full Functional & Security Gates)

The test suite must verify:
1. `GET /api/v1/departments/analytics` aggregates live company metrics (total, active, archived, assigned staff, staffed units, empty units, unassigned heads, and department breakdown).
2. `GET /api/v1/departments/heads/candidates` returns complete employee profiles (avatar, designation title, department name, employeeCode, email, status).
3. `GET /api/v1/departments/heads/candidates?search=...` filters candidates accurately.
4. `GET /api/v1/departments/:id` returns single department details with the complete assigned staff roster (`employees` array with designations).
5. `GET /api/v1/departments` returns active departments (supporting legacy unpopulated records).
6. `PATCH /api/v1/departments/:id/archive` archives department and excludes it from active listing.
7. `POST /api/v1/employees` blocks assigning employees to archived departments.
8. `DELETE /api/v1/departments/:id/permanent` is **strictly BLOCKED** when $\ge 1$ employee is assigned (HTTP 400 with employee warning message).
9. `DELETE /api/v1/departments/:id/permanent` succeeds once all employees are reassigned.
10. `PATCH /api/v1/departments/:id/restore` reinstates archived department with code conflict checks.
11. Unauthorized roles (Employee) are strictly forbidden from creating, updating, archiving, or deleting departments.
12. Audit logs are correctly recorded for all lifecycle transitions.
