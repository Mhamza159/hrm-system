# Plan 25-01: Backend Schema Expansion, Archival Lifecycle & Employee Assignment Restriction Guard

**Phase**: 25 · Department Module — Complete Audit, Implementation, Archive Management & UI/UX Refinement  
**Plan ID**: 25-01  
**Goal**: Expand `Department` schema to support explicit archival tracking, implement service-layer archive, restore, and permanent delete methods with strict sub-department guards and the non-negotiable **Employee Assignment Restriction Guard**.

---

## 1. Scope of Work

1. **Schema Expansion (`backend/src/models/department.model.js`)**:
   - Add archival fields:
     - `isArchived: { type: Boolean, default: false, index: true }`
     - `archivedAt: { type: Date, default: null }`
     - `archivedBy: { type: mongoose.Schema.Types.ObjectId, ref: 'User', default: null }`
   - Add compound indexes:
     - `{ isArchived: 1, isDeleted: 1 }`
     - `{ parentId: 1, isArchived: 1 }`
     - `{ code: 1, isDeleted: 1 }`

2. **Domain Service Implementation (`backend/src/modules/departments/department.service.js`)**:
   - **`archiveDepartment(id, actor)`**:
     - Check if department exists and is not already archived or deleted.
     - Verify no active sub-departments report to it (`parentId: id, isArchived: false, isDeleted: false`). If so, reject with 400: *"Cannot archive department. Sub-departments report to it. Reassign or archive sub-departments first."*
     - Mark `isArchived: true`, `archivedAt: new Date()`, `archivedBy: actor._id`.
     - Record audit log `department.archive`.
   - **`restoreDepartment(id, actor)`**:
     - Check if department exists and is archived.
     - Verify code uniqueness among active departments (in case another department reused the code while archived).
     - If `parentId` is set, check if the parent department is active (if parent is archived/deleted, clear `parentId` to null or warn).
     - Clear `isArchived: false`, `archivedAt: null`, `archivedBy: null`.
     - Record audit log `department.restore`.
   - **`permanentDeleteDepartment(id, actor)` (CRITICAL GUARD)**:
     - Check if department exists (must be in archived state or found by id).
     - **Employee Assignment Restriction**:
       ```javascript
       const assignedCount = await Employee.countDocuments({ departmentId: id });
       if (assignedCount > 0) {
         throw new ApiError(
           400,
           `This department cannot be permanently deleted because ${assignedCount} employee(s) are still assigned to it. Please reassign all employees to another department before proceeding.`
         );
       }
       ```
     - **Sub-Department Guard**: Check `Department.countDocuments({ parentId: id }) == 0`.
     - Execute permanent deletion: `await Department.deleteOne({ _id: id })` (or mark `isDeleted: true`).
     - Record audit log `department.permanent_delete`.

3. **Active Queries Filter Update (`backend/src/modules/departments/department.service.js`)**:
   - Ensure `getAllDepartments` filters `{ isArchived: false, isDeleted: false }` so archived departments do not appear in the active listing.
   - Attach populated `archivedBy` user info for archived records.

4. **Validation Schemas (`backend/src/modules/departments/department.validation.js`)**:
   - Add validation for archive, restore, and permanent deletion parameters.

---

## 2. Verification Criteria
- [ ] Schema reflects `isArchived`, `archivedAt`, and `archivedBy`.
- [ ] Attempting to permanently delete a department with $\ge 1$ assigned employee throws 400 with the exact error message.
- [ ] Attempting to permanently delete a department with 0 employees successfully deletes the record.
- [ ] Archiving and restoring correctly toggles `isArchived` and maintains audit trail.
