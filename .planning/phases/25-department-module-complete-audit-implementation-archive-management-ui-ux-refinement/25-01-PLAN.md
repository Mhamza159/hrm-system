# Plan 25-01: Backend Analytics Aggregation & Rich Searchable Employee Candidates API

**Phase**: 25 · Department Module — Complete UI Overhaul, Functional Audit, Analytics, RBAC/PBAC Compliance & Error Fixing  
**Plan ID**: 25-01  
**Goal**: Implement comprehensive backend analytics aggregation (`GET /api/v1/departments/analytics`), expand `getDepartmentById` to populate the full staff roster with designations, and upgrade `getHeadCandidates` to support real-time search and return complete employee profiles (avatar, designation, department, employee code, status).

---

## 1. Scope of Work

1. **Department Analytics Service & Endpoint (`GET /api/v1/departments/analytics`)**:
   - Aggregate live company workforce metrics:
     - `totalDepartments`: Total count of departments (`isDeleted: false`).
     - `activeDepartments`: Count of active departments (`isArchived: { $ne: true }, isDeleted: false`).
     - `archivedDepartments`: Count of archived departments (`isArchived: true, isDeleted: false`).
     - `totalAssignedEmployees`: Total employees assigned to any active department (`isDeleted: false`).
     - `staffedDepartments`: Count of departments with $\ge 1$ employee.
     - `emptyDepartments`: Count of active departments with 0 employees.
     - `unassignedHeads`: Count of active departments where `headId` is null.
     - `headAssignmentRatio`: Percentage of departments with assigned leadership.
     - `departmentBreakdown`: Array of active departments with `_id`, `name`, `code`, `headcount`, `percentage` of total company workforce, and `hasHead`.
     - `topDepartment`: Department with highest employee headcount.
     - `lowestDepartment`: Department with lowest employee headcount (among staffed units).
   - Controller & Route registration:
     - `department.controller.js` -> `getDepartmentAnalytics`.
     - `department.routes.js` -> `router.get('/analytics', checkPermission('org.view'), departmentController.getDepartmentAnalytics)`.
     - Note: Mount `/analytics` **before** `/:id` to prevent ObjectId collisions.

2. **Rich Searchable Employee Candidates API (`GET /api/v1/departments/heads/candidates`)**:
   - Upgrade `getHeadCandidates` in `department.service.js` to accept `search`:
     ```javascript
     export const getHeadCandidates = async ({ search = '' } = {}) => { ... }
     ```
   - Populate employee details:
     - `employeeId` -> populate `name, employeeCode, avatar, status, departmentId, designationId`.
     - Populate nested `designationId` to get `title, grade`.
     - Populate nested `departmentId` to get current `name, code`.
   - Return clean candidate contract:
     ```javascript
     {
       _id: user._id,
       email: user.email,
       name: user.employeeId?.name || user.email,
       employeeCode: user.employeeId?.employeeCode || '—',
       avatar: user.employeeId?.avatar || null,
       designation: user.employeeId?.designationId?.title || 'Staff Member',
       currentDepartment: user.employeeId?.departmentId?.name || 'Unassigned',
       status: user.employeeId?.status || 'Active'
     }
     ```
   - Zero generic labels ("Employee 1"); 100% authentic database personnel.

3. **Staff Roster Enrichment in `getDepartmentById`**:
   - In `getDepartmentById`, fetch assigned employees:
     ```javascript
     const employees = await Employee.find({ departmentId: id, isDeleted: false })
       .select('name employeeCode email designationId status joiningDate avatar')
       .populate('designationId', 'title grade')
       .sort({ name: 1 })
       .lean();
     ```
   - Return `{ ...department, headName, headcount, employees }`.

4. **RTK Query Endpoints (`frontend/src/features/departments/departmentsApi.js`)**:
   - Add `getDepartmentAnalytics` query (`/departments/analytics`), tagged with `'DepartmentAnalytics'`.
   - Add search parameter support to `getHeadCandidates` query.
