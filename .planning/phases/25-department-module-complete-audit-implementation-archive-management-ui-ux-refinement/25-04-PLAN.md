# Plan 25-04: Complete Modals Suite (Detail, Archive, Restore, and Permanent Delete with Employee Guard) & End-to-End Verification

**Phase**: 25 · Department Module — Complete Audit, Implementation, Archive Management & UI/UX Refinement  
**Plan ID**: 25-04  
**Goal**: Design and implement the full suite of department modals (Create/Edit, Detail, Archive, Restore, and Permanent Delete with Employee Assignment Restriction Guard), and establish an exhaustive Vitest integration test suite verifying the complete department lifecycle.

---

## 1. Scope of Work

1. **Department Create & Edit Modal (`frontend/src/features/departments/components/DepartmentModal.jsx`)**:
   - Refine design to Forest & Emerald standards: clean input fields, monospace uppercase code input with validation, searchable parent selector (excluding self and circular candidates), head candidate selector, active switch.
   - Real-time client and server validation error handling with informative alerts.

2. **Department Detail Inspection Modal (`frontend/src/features/departments/components/DepartmentDetailModal.jsx`)**:
   - Section A: Directorate & Identity (Name, Code badge, Description, Status, Created / Last Updated timestamps in `Asia/Karachi`).
   - Section B: Hierarchy & Leadership (Parent Division pill, Department Head with avatar and email).
   - Section C: Assigned Staff Roster preview (List of assigned employees with `PersonAvatar`, names, codes, and designations).

3. **Archive Department Confirmation Modal (`frontend/src/features/departments/components/DepartmentArchiveModal.jsx`)**:
   - Clear explanation: *"Archiving this department moves it to cold storage. Existing staff remain associated for historical records, but new employee assignments and sub-departments will be blocked."*
   - Displays department name, code, and current headcount.
   - Cancel and Confirm Archive actions with loading spinner.

4. **Restore Department Confirmation Modal (`frontend/src/features/departments/components/DepartmentRestoreModal.jsx`)**:
   - Explains that the department will return to the active directory.
   - Pre-checks code uniqueness and parent division status.
   - Cancel and Confirm Restore actions with loading spinner.

5. **Permanent Delete Modal with Strict Employee Guard (`frontend/src/features/departments/components/DepartmentPermanentDeleteModal.jsx`)**:
   - **CRITICAL BUSINESS RULE ENFORCEMENT**:
     - Evaluates `department.headcount`:
     - **If `headcount > 0`**:
       - Displays prominent high-contrast red blocker alert:
         > **Permanent Deletion Blocked**  
         > *"This department cannot be permanently deleted because **{headcount} employee(s)** are still assigned to it. Please reassign all employees to another department before proceeding."*
       - The "Permanently Delete" button is **disabled** with an explanatory tooltip.
       - Provides direct action link/guidance to the Employee Directory for reassignment.
     - **If `headcount === 0`**:
       - Displays strong danger warning that this operation is permanent and irreversible.
       - Requires explicit confirmation.
       - Executes `permanentDeleteDepartment(id)`.

6. **Comprehensive Vitest Integration Test Suite (`backend/tests/departments.archive-lifecycle.e2e.test.js`)**:
   - Test 1: Department creation with code uniqueness and parent division hierarchy.
   - Test 2: Circular hierarchy detection blocks circular parent assignment.
   - Test 3: Archiving department sets `isArchived: true` and archive metadata.
   - Test 4: Archived department appears in `GET /departments/archived` and is omitted from `GET /departments`.
   - Test 5: Employee creation/update fails when assigning to an archived department.
   - Test 6: **CRITICAL**: Permanent delete request for a department with assigned employees is **rejected with HTTP 400** and informative error message.
   - Test 7: Reassigning employees to another department lowers headcount to 0.
   - Test 8: Permanent delete request for an empty department succeeds and removes it from the database.
   - Test 9: Restoring an archived department reinstates it to active status.
   - Test 10: `GET /departments/stats` aggregates accurate live counts across active, archived, and staff allocations.
   - Test 11: Non-authorized users (`Employee` role) cannot archive, restore, or delete departments.

7. **Verification Gate**:
   - Run Vitest suite: 100% passed.
   - Run Oxlint on frontend departments feature: 0 errors, 0 warnings.
   - Run Vite production build: Clean build.
