# Plan 25-02: RBAC & PBAC Compliance, Authorization Audit & Backend API Verification

**Phase**: 25 · Department Module — Critical Regression Fix, Complete Audit, RBAC/PBAC Compliance & UI/UX Refinement  
**Plan ID**: 25-02  
**Goal**: Perform a complete authorization audit against official docs (`docs/TECH-SPEC.md`, `backend/src/shared/permissions.js`, `checkPermission.js`), ensuring strict RBAC/PBAC compliance across all department routes, controllers, and services without weakening or bypassing any permissions.

---

## 1. Documentation & Permission Matrix Alignment

- Mandatory documented permissions:
  - `action: 'org.view'`, `subject: 'Organization'`: Required for all read-only department operations (listing, details, stats, archived list, heads, candidates, org chart).
  - `action: 'org.manage'`, `subject: 'Organization'`: Required for all administrative mutating operations (create, update, head assignment, archive, restore, permanent delete).
- Policy-Based Access Control (PBAC):
  - Data scopes (`all`, `department`, `team`, `own`): Super Admin & HR Manager hold `scope: 'all'`. Department Managers hold `scope: 'department'`. Employees hold `scope: 'own'`/`'all'` for directory viewing.
  - Controllers must respect scope without breaking company-wide organizational directory viewing.

---

## 2. Scope of Work

1. **Route Middleware Audit (`backend/src/modules/departments/department.routes.js`)**:
   - Verify every endpoint enforces `authenticate` and `checkPermission`:
     - `GET /` -> `checkPermission('org.view')`
     - `GET /stats` -> `checkPermission('org.view')`
     - `GET /archived` -> `checkPermission('org.view')`
     - `GET /heads/candidates` -> `checkPermission('org.view')`
     - `GET /:id` -> `checkPermission('org.view')`
     - `POST /` -> `checkPermission('org.manage')`
     - `PATCH /:id` -> `checkPermission('org.manage')`
     - `PATCH /:id/head` -> `checkPermission('org.manage')`
     - `PATCH /:id/archive` -> `checkPermission('org.manage')`
     - `PATCH /:id/restore` -> `checkPermission('org.manage')`
     - `DELETE /:id/permanent` -> `checkPermission('org.manage')`
   - Route registration order invariant: Ensure `/stats`, `/archived`, and `/heads/candidates` are mounted **BEFORE** `/:id` to prevent ObjectId parameter collisions.

2. **Controller Audit (`backend/src/modules/departments/department.controller.js`)**:
   - Ensure clean validation via Zod schemas.
   - Extract actor context (`req.user._id`, `req.user.email`, `req.user.roles`, `req.ip`) safely.
   - Enforce standard response envelope: `apiResponse(200, data, message, meta/pagination)`.

3. **Employee Guard Integration (`backend/src/modules/employees/employee.service.js`)**:
   - Audit `createEmployee` and `updateEmployee` to ensure assignment to an archived or deleted department is strictly rejected with HTTP 400.

4. **Verification**:
   - Verify that Employee token receives 403 Forbidden on `PATCH /archive`, `PATCH /restore`, and `DELETE /permanent`.
   - Verify that Admin and HR Manager tokens can execute authorized actions seamlessly.
