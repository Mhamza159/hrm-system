# Plan 24-02: Comprehensive Audit Query APIs, Aggregated Stats & Multi-Format Data Export

## Goal
Implement advanced query filtering, high-speed aggregation statistics, record detail inspection, and secure CSV/Excel export endpoints on the backend, enforcing strict PBAC and RBAC security boundaries.

## Proposed Changes

### 1. `backend/src/modules/auth/auth.validation.js`
- Create query schema `getLoginHistoryQuerySchema`:
  - `page`: positive integer (default 1).
  - `limit`: positive integer (default 20, max 100).
  - `startDate`: optional ISO date string.
  - `endDate`: optional ISO date string.
  - `status`: optional enum (`SUCCESS`, `FAILED`, `LOCKED`, `BLOCKED`, `RESTRICTED`, `2FA_PENDING`, `2FA_FAILED`, `ALL`).
  - `deviceType`: optional enum (`DESKTOP`, `MOBILE`, `TABLET`, `UNKNOWN`, `ALL`).
  - `role`: optional string.
  - `search`: optional search string (searches `email`, `employeeName`, `ipAddress`, `failureReason`).

### 2. `backend/src/modules/auth/auth.service.js`
- Update `getLoginHistory({ userId, userRoles, permissionScope, query })`:
  - Construct dynamic MongoDB query supporting:
    - `createdAt: { $gte: startDate, $lte: endDate }`.
    - `status`: specific status filter.
    - `deviceType`: specific device filter.
    - `role`: specific role filter.
    - `$or` search over `email`, `employeeName`, `ipAddress`, `browser`, `os`.
  - Enforce permission scoping:
    - If caller has `scope: 'own'` (non-admin), force `userId: new mongoose.Types.ObjectId(userId)`.
    - If caller is Super Admin or HR Manager (`scope: 'all'`), allow company-wide search and optional `userId` / `email` filtering.
- Implement `getLoginHistoryStats({ userId, userRoles, permissionScope, query })`:
  - Execute a high-performance MongoDB aggregation pipeline returning:
    - `totalAttempts`: Total count of attempts in date range.
    - `successfulLogins`: Count of `status === 'SUCCESS'`.
    - `failedLogins`: Count of `status === 'FAILED'`.
    - `lockedAttempts`: Count of `status === 'LOCKED'`.
    - `twoFactorChallenges`: Count of `status === '2FA_PENDING'`.
    - `uniqueUsers`: Count of distinct `email` values.
    - `successRate`: Percentage of successful attempts.
- Implement `getLoginHistoryDetail(id, { userId, userRoles, permissionScope })`:
  - Look up attempt by ID.
  - Verify caller ownership (if `scope: 'own'`, ensure record belongs to `userId`).
  - Compute consecutive failure count from same IP or account in last 24 hours.
  - Return enriched attempt detail object.
- Implement `exportLoginHistory({ userId, userRoles, permissionScope, query, format })`:
  - Supports `csv` format.
  - Generates properly escaped CSV lines with headers:
    `Timestamp (PKT),Email,Employee Name,Role,Department,Status,IP Address,Device,Browser,OS,Failure Reason`.
  - Strips any sensitive credentials; exports strictly up to 10,000 records.

### 3. `backend/src/modules/auth/auth.controller.js`
- Update `getLoginHistory` to accept full validated query params.
- Add `getLoginHistoryStats`: returns `{ statusCode: 200, success: true, data: stats, message: 'Stats computed successfully' }`.
- Add `getLoginHistoryDetail`: returns `{ statusCode: 200, success: true, data: detail, message: 'Attempt details retrieved' }`.
- Add `exportLoginHistory`: sets `Content-Disposition: attachment; filename="login-history-export.csv"` and streams CSV response.

### 4. `backend/src/modules/auth/auth.routes.js`
- Register endpoints with authentication and permission checks:
  - `GET /api/v1/auth/login-history` -> `checkPermission('login.history')` -> `getLoginHistory`.
  - `GET /api/v1/auth/login-history/stats` -> `checkPermission('login.history')` -> `getLoginHistoryStats`.
  - `GET /api/v1/auth/login-history/export` -> `checkPermission('login.history')` -> `exportLoginHistory`.
  - `GET /api/v1/auth/login-history/:id` -> `checkPermission('login.history')` -> `getLoginHistoryDetail`.

## Verification Criteria
- [ ] `GET /api/v1/auth/login-history` filters accurately by date range, status, device, and keyword search.
- [ ] `GET /api/v1/auth/login-history/stats` returns accurate aggregated counts from database records.
- [ ] `GET /api/v1/auth/login-history/:id` retrieves single record details with permission enforcement.
- [ ] `GET /api/v1/auth/login-history/export` streams clean CSV with properly escaped quotes and headers.
- [ ] Employees can never see records or stats outside their own `userId`.
