# Plan 24-01: Backend Architecture, Schema Expansion, User-Agent Parsing & Authentication Event Instrumentation

## Goal
Upgrade the `LoginHistory` database model with complete employee snapshot fields, granular client environment fields (`browser`, `os`, `location`), expanded status enums (`BLOCKED`, `RESTRICTED`, `2FA_FAILED`), high-performance compound indexes, and create a lightweight zero-dependency user-agent parser (`userAgentParser.js`). Instrument all authentication flows in `auth.service.js` so that every successful, failed, locked, inactive, and 2FA challenge attempt is reliably captured with complete contextual metadata.

## Proposed Changes

### 1. `backend/src/models/loginHistory.model.js`
- Expand schema with identity and environment fields:
  - `employeeId: { type: mongoose.Schema.Types.ObjectId, ref: 'Employee', default: null, index: true }`
  - `employeeName: { type: String, default: null, trim: true }`
  - `employeeCode: { type: String, default: null, trim: true }`
  - `role: { type: String, default: null, trim: true }`
  - `department: { type: String, default: null, trim: true }`
  - `location: { type: String, default: 'Local / Private Network', trim: true }`
  - `browser: { type: String, default: 'Unknown Browser' }`
  - `os: { type: String, default: 'Unknown OS' }`
- Expand `status` enum:
  - `enum: ['SUCCESS', 'FAILED', 'LOCKED', 'BLOCKED', 'RESTRICTED', '2FA_PENDING', '2FA_FAILED']`
- Add compound indexes:
  - `{ createdAt: -1, status: 1 }`
  - `{ userId: 1, createdAt: -1 }`
  - `{ email: 1, createdAt: -1 }`
  - `{ ipAddress: 1, createdAt: -1 }`
  - Maintain 90-day TTL index on `createdAt`.

### 2. `backend/src/utils/userAgentParser.js`
- Create a lightweight, high-speed user-agent parser using standard regular expressions without external npm dependencies:
  - Extracts `browser`: Chrome, Firefox, Safari, Edge, Opera, Samsung Internet, Internet Explorer, or Unknown + major version.
  - Extracts `os`: Windows (10/11/Server), macOS (with version), iOS, Android, Linux, Chrome OS, or Unknown.
  - Extracts `deviceType`: `DESKTOP`, `MOBILE`, `TABLET`, or `UNKNOWN`.
  - Normalizes IP addresses (IPv4, IPv6, localhost `::1` or `::ffff:127.0.0.1` mapped to readable format).

### 3. `backend/src/modules/auth/auth.service.js`
- Create helper `recordLoginAttempt({ userId, email, ipAddress, userAgent, status, failureReason, userDoc })`:
  - Parses client information via `parseUserAgent(userAgent)`.
  - If `userDoc` is provided or found, look up linked `Employee` to capture `employeeId`, `employeeName`, `employeeCode`, `department`, and primary `role`.
  - Gracefully handles unknown accounts (stores `email`, `status: 'FAILED'`, `failureReason: 'Invalid credentials'`, and `employeeName: 'Unregistered Account'` without revealing user existence).
- Instrument every authentication gate in `AuthService`:
  - **Unknown User (`!user`)**: Record `status: 'FAILED'`, `failureReason: 'Invalid credentials'` (Timing mitigation preserved).
  - **Inactive Account (`!user.isActive`)**: Record `status: 'RESTRICTED'`, `failureReason: 'Account deactivated by administrator'`.
  - **Account Locked (`user.lockUntil > now`)**: Record `status: 'LOCKED'`, `failureReason: 'Account locked due to consecutive failed attempts'`.
  - **Wrong Password (`!isMatch`)**: Record `status: 'FAILED'`, `failureReason: 'Invalid password'`. If attempts trigger lock, also record lockout transition.
  - **2FA Required (`user.isTwoFactorEnabled`)**: Record `status: '2FA_PENDING'`, `failureReason: 'Two-factor authentication challenge issued'`.
  - **2FA Verification Success (`verifyLogin2FA`)**: Record `status: 'SUCCESS'`, `failureReason: '2FA verification completed successfully'`.
  - **2FA Verification Failure (`verifyLogin2FA`)**: If code is invalid or expired, record `status: '2FA_FAILED'`, `failureReason: 'Invalid or expired 2FA code'`.
  - **Standard Login Success**: Record `status: 'SUCCESS'`, `failureReason: 'Authentication successful'`.

## Verification Criteria
- [ ] Schema contains all expanded fields with compound indexes and 90-day TTL eviction.
- [ ] `parseUserAgent()` correctly identifies Chrome, Firefox, Safari, Edge, Windows, macOS, Android, and iOS.
- [ ] Successful logins generate records with parsed browser, OS, and employee identity.
- [ ] Failed password logins create records with `status: 'FAILED'` and meaningful reason.
- [ ] Locked account attempts generate records with `status: 'LOCKED'`.
- [ ] 2FA challenge and verification events generate structured `2FA_PENDING` and `SUCCESS` / `2FA_FAILED` records.
