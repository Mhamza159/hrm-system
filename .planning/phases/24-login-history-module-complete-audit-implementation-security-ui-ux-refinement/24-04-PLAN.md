# Plan 24-04: Detailed Login Inspection Modal, Suspicious Activity Alerts, Security Guards & Verification Gate

## Goal
Design and implement a comprehensive login attempt inspection modal (`LoginDetailModal.jsx`), integrate suspicious activity warning banners (`SecurityAlertBanner.jsx`), build an end-to-end integration test suite (`backend/tests/auth.login-history.e2e.test.js`), and pass all verification gates (100% test pass rate, 0 Oxlint warnings, and clean Vite production build).

## Proposed Changes

### 1. `frontend/src/features/auth/components/LoginDetailModal.jsx`
- Create an enterprise inspection dialog/drawer matching the Forest & Emerald design:
  - **Header**:
    - Status pill (`SUCCESS`, `FAILED`, `LOCKED`, etc.).
    - Exact localized timestamp in `Asia/Karachi`.
    - Close button (`Esc` key and backdrop click supported).
  - **Section A: Account Identity & Organization**:
    - Employee Name, Employee Code, Account ID, Email address.
    - Role badge and Department name.
    - Account status at time of attempt (Active / Deactivated).
  - **Section B: Authentication Outcome & Notice**:
    - Outcome status, Event type (Password Login, 2FA Verification, Emergency Reset).
    - Failure classification & plain-English notice.
  - **Section C: Network & Location**:
    - IP address (with one-click copy button).
    - Approximate location (`Local / Private Network` or Region).
    - Forwarded proxy verification badge.
  - **Section D: Client Environment & Device**:
    - Device Type (Desktop, Mobile, Tablet) with corresponding icon.
    - Operating System & Browser version breakdown.
  - **Section E: Security Context & Threat Correlation**:
    - Recent consecutive failures from same IP or account in the last 24 hours.
    - Lockout status indicator.
    - Technical User-Agent collapsible view with copy CTA.

### 2. `frontend/src/features/auth/components/SecurityAlertBanner.jsx`
- Reusable alert component placed above the table:
  - Appears when the active filter window contains account lockout occurrences (`status: 'LOCKED'`) or consecutive failure spikes.
  - Displays count of locked accounts with quick filter link to isolate security events.
  - Dismissible with smooth fade animation.

### 3. `backend/tests/auth.login-history.e2e.test.js`
- Create a comprehensive Vitest integration suite testing all 15 audit criteria:
  1. `POST /api/v1/auth/login` creates a `SUCCESS` record with parsed browser, OS, and employee snapshot.
  2. Failed login with wrong password generates `FAILED` record with `failureReason: 'Invalid password'`.
  3. Login attempt with unregistered email generates `FAILED` record without user account enumeration leak.
  4. Deactivated user login generates `RESTRICTED` record with `failureReason: 'Account deactivated by administrator'`.
  5. 5 consecutive wrong passwords trigger account lockout and record `status: 'LOCKED'`.
  6. 2FA challenge generates `status: '2FA_PENDING'`.
  7. Successful 2FA verification creates `status: 'SUCCESS'`.
  8. Failed 2FA verification creates `status: '2FA_FAILED'`.
  9. `GET /api/v1/auth/login-history` supports status and date-range filtering.
  10. `GET /api/v1/auth/login-history` supports keyword search across email, employee name, and IP.
  11. `GET /api/v1/auth/login-history/stats` returns accurate aggregated metrics.
  12. `GET /api/v1/auth/login-history/:id` returns enriched attempt details.
  13. `GET /api/v1/auth/login-history/export` streams well-formatted CSV with appropriate headers.
  14. Employee with `scope: 'own'` can only view and export their own records (data isolation).
  15. Unauthenticated or unauthorized callers receive 401/403.
