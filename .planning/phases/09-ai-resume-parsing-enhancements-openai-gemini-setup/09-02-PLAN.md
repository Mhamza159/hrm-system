# Plan 09-02: Multi-Provider AI Architecture & OpenAI / Gemini Failover

## Objective
Establish a flexible, enterprise-grade multi-provider AI architecture supporting both **Google Gemini** (`gemini-2.5-flash`) and **OpenAI** (`gpt-4o-mini`). Add runtime provider routing (`AI_PROVIDER=auto|gemini|openai`), configure `OPENAI_API_KEY`, and implement automatic cross-provider failover when quota limits (HTTP 429) are encountered.

---

## Tasks

### 1. Environment Configuration (`backend/.env` & `backend/src/config/env.js`)
- Add `OPENAI_API_KEY` placeholder / configuration entry to `backend/.env`.
- Add `AI_PROVIDER` (`auto`, `gemini`, `openai`) defaulting to `auto`.
- Export `AI_PROVIDER` in `backend/src/config/env.js`.

### 2. Provider Routing & Failover Architecture (`backend/src/services/ai.service.js`)
- Refactor `getAiConfig()` to support multiple providers with prioritized order:
  - If `AI_PROVIDER === 'gemini'`: Try Gemini only.
  - If `AI_PROVIDER === 'openai'`: Try OpenAI only.
  - If `AI_PROVIDER === 'auto'` (Default): Order providers based on configured keys (`['gemini', 'openai']` or `['openai', 'gemini']`).
- Implement `callLlmWithFailover(systemPrompt, userPrompt, jsonSchema)`:
  - Iterate through available providers.
  - If a provider fails with HTTP 429 (quota exceeded), log a warning and seamlessly retry with the next configured provider.
  - If all cloud providers fail or are unconfigured, smoothly fall back to `heuristicResumeParser` and deterministic scoring formula.
- Standardize JSON Schema payload across both providers so response formats are identical.

### 3. Provider Testing (`backend/tests/m15.multiProvider.test.js`)
- Test provider selection under `AI_PROVIDER=auto`, `AI_PROVIDER=gemini`, and `AI_PROVIDER=openai`.
- Mock a 429 quota error on primary provider and verify automatic failover to secondary provider.
- Verify schema uniformity: both models return identical JSON keys (`candidateName`, `parsedSkills`, `totalExperienceYears`, `highestEducation`, `executiveSummary`).
