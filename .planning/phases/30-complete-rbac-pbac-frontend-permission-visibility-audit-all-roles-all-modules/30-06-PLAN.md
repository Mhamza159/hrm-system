# Plan 30-06: End-to-End Multi-Role Automated Testing, Visibility Matrix & Verification Report

## Goal
Author an automated test suite verifying multi-role frontend visibility and backend enforcement across 9 distinct role profiles. Verify that missing or revoked permissions completely hide corresponding UI elements and that backend APIs reject unauthorized requests with HTTP 403. Compile the comprehensive Role-Permission Visibility Matrix and produce the final audit report.

## Target Files
- `backend/tests/rbac.pbac.visibility.audit.test.js`
- `docs/ROLE-PERMISSION-VISIBILITY-MATRIX.md`

## Detailed Implementation Tasks
1. **Automated Vitest Test Suite (`backend/tests/rbac.pbac.visibility.audit.test.js`)**:
   - Seed and test 9 distinct role personas:
     1. `Super Admin`: Unrestricted global visibility across all 26 modules.
     2. `HR Manager`: Workforce, payroll, attendance, leave, and announcements management. Restricted from Super Admin delegation or company root settings.
     3. `Department Manager`: Departmental attendance/leave approvals and team directory. Restricted from payroll runs, role editing, and system settings.
     4. `Employee`: Personal self-service (punch, apply leave, view profile). Restricted from all managerial actions.
     5. `Custom Role A (View Only)`: Holds `employee.view`, `org.view`, `payroll.view`. Verifies create, edit, delete, and run triggers are 100% hidden and blocked.
     6. `Custom Role B (View + Create)`: Holds `employee.create` without edit/delete.
     7. `Custom Role C (View + Edit)`: Holds `employee.edit` without create/delete.
     8. `Custom Role D (View + Delete)`: Holds `employee.delete` without edit/create.
     9. `Revoked Role Persona`: Dynamically revokes a granted permission (e.g. `leave.approve`) and verifies the action immediately disappears and API rejects with HTTP 403.
   - Verify that direct API calls attempting to execute restricted operations (e.g. creating employee, running payroll, deleting role) return HTTP 403 Forbidden.
2. **Author Role-Permission Visibility Matrix (`docs/ROLE-PERMISSION-VISIBILITY-MATRIX.md`)**:
   - Generate a markdown table mapping all modules and key actions against each role:
     - Visible vs Completely Hidden
     - Allowed Data Scopes (`all`, `department`, `team`, `own`)
     - Backend API Middleware validation status
3. **Static Analysis & Build Verification**:
   - Run Oxlint across frontend and backend ensuring 0 errors.
   - Run Vite production build ensuring a clean bundle.
4. **Final Audit Report & Documentation**:
   - Total roles audited: 9 personas.
   - Total modules audited: 26 modules.
   - Summarize discovered and resolved visibility gaps.

## Verification & Acceptance Criteria
- Vitest suite `rbac.pbac.visibility.audit.test.js` executes and passes with 100% green tests.
- 0 Oxlint errors across all project files.
- Clean Vite production build.
- Complete Role-Permission Visibility Matrix published in `docs/ROLE-PERMISSION-VISIBILITY-MATRIX.md`.
