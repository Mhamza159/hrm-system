# Plan 30-01: Centralized Permission Primitives, Real-Time Revocation & Auth Sync Engine

## Goal
Establish a robust, real-time centralized frontend permission evaluation and revocation sync engine. Ensure that when an administrator updates permissions or assigns/revokes roles in the database, the active user's permissions and CASL ability instance automatically synchronize without requiring a manual logout/login cycle. Standardize `<Can />`, `usePermission()`, and `ProtectedRoute.jsx` with strict Admin exemption rules (`manage:all`), ensuring unauthorized elements never render in the DOM.

## Target Files
- `frontend/src/features/auth/authApi.js`
- `frontend/src/features/auth/authSlice.js`
- `frontend/src/App.jsx`
- `frontend/src/lib/ability.js`
- `frontend/src/hooks/usePermission.js`
- `frontend/src/components/common/Can.jsx`
- `frontend/src/components/ProtectedRoute.jsx`

## Detailed Implementation Tasks
1. **Real-Time Revocation & Session Rehydration (`authApi.js`, `App.jsx`, `authSlice.js`)**:
   - Update `authApi.js`: Enhance `getMe` query with `onQueryStarted` lifecycle to automatically update Redux `state.auth.user` with the latest populated roles and additive permissions upon tag invalidation (`['Auth']`).
   - In `App.jsx`: Mount `useGetMeQuery(undefined, { skip: !isAuthenticated })` at application root to listen to `'Auth'` cache tag invalidations triggered by role mutations or delegations.
   - When a permission is revoked, the updated user permissions immediately propagate to Redux and trigger re-computation of CASL `ability` in `AbilityProvider`.
2. **Centralized CASL Ability & Hook Optimization (`ability.js`, `usePermission.js`)**:
   - Audit `buildAbilityFromRules`: Verify that `Super Admin` and any role holding `action: 'manage', subject: 'all'` gets unconditional `can('manage', 'all')`.
   - Ensure `usePermission` provides fast, memoized `can(action, subject = 'all', field = undefined)` and `cannot(...)`.
   - Enforce that unauthorized checks return `false`, preventing UI rendering.
3. **Declarative Component Guarding (`Can.jsx`)**:
   - Ensure `<Can I="action" a="subject">` strictly returns `fallback` (defaulting to `null`) when unauthorized.
   - Verify zero DOM leakage: no empty wrappers, no disabled hidden buttons, no placeholder tags.
4. **Route Guarding Hardening (`ProtectedRoute.jsx`)**:
   - Audit all route guards. If a user attempts direct navigation to a revoked or unauthorized route:
     - Check `isSuperAdmin || can(requiredPermission)`.
     - Render `PermissionDeniedState` or redirect to `/`, completely shielding internal page logic, data fetches, and child components.

## Verification & Acceptance Criteria
- Triggering a role permission update or user role assignment immediately updates the frontend permission state in real-time.
- Revoked permissions cause corresponding navigation and UI elements to unmount immediately.
- Super Admin retains full administrative access across all checks.
- Zero console errors or infinite re-render loops during permission synchronization.
