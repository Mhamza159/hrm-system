# Plan 16-02: Track Case Submodule Audit, UI Redesign & Dual-Mode Tracking

## 1. Goal
Audit, modernize, and completely redesign the **Track Case** submodule (`TrackFeedbackPage.jsx`). Introduce dual tracking modes: a **Confidential Code Lookup** for anonymous complainants, and an integrated **My Submitted Cases** view for authenticated employees (powered by `useGetMyFeedbackSubmissionsQuery`), complete with a 4-stage visual timeline, sanitized public investigator notes, resolution conclusions, and Forest & Emerald Enterprise styling.

---

## 2. Target Files & Scope
- `frontend/src/features/feedback/pages/TrackFeedbackPage.jsx`

---

## 3. Detailed Tasks

### Task 1: Dual-Mode Segmented Tabs & Code Search Bar
- Introduce top-level segmented navigation:
  - **Tab 1: Confidential Code Lookup**: For anonymous cases or quick reference search (`TRK-XXXXXX`).
  - **Tab 2: My Submitted Cases**: For authenticated employees to view all their named submissions without memorizing codes.
- Redesign Code Search Input:
  - Monospaced code input field with uppercase auto-formatting.
  - Search icon, clear button, and "Track Progress" CTA.
  - URL parameter synchronization (`?code=TRK-XXXXXX`).

### Task 2: 4-Stage Visual Status Timeline
- Implement a responsive horizontal / vertical progress tracker:
  - Step 1: **Registered / Submitted** (Case officially logged in the system).
  - Step 2: **Under Review** (Assigned to investigator / initial triage).
  - Step 3: **In Investigation** (Evidence gathering, witness hearings, notes recorded).
  - Step 4: **Resolved / Closed** (Formal resolution recorded or case closed).
- State indicators: Active step with emerald glow, completed steps with checkmark icon, and future steps with muted hairline circles.
- Special handling for `Dismissed` or `Escalated` statuses with distinct badges.

### Task 3: Case Details & Sanitized Public Notes Feed
- **Case Summary Card**:
  - Tracking code pill (`font-mono`), category tag, priority badge (Low, Medium, High, Urgent), and target department.
  - Case subject and full description.
  - Submission date and last updated timestamp (`font-mono tabular-nums`).
- **Official Resolution Section**:
  - If status is `Resolved` or `Dismissed`, display the formal `resolutionNote` in an emerald/neutral card with resolution date and resolved by role.
- **Public Case Notes & Updates**:
  - Feed of sanitized case updates (`isPublicToComplainant: true`) showing update date, investigator role, and update text.
  - Internal administrative deliberations remain strictly excluded per the backend API contract.

### Task 4: "My Submitted Cases" Authenticated List
- For logged-in users, render an elegant data table / card list of their submitted grievances:
  - Columns: Tracking Code, Subject, Category, Priority, Current Status, Submitted Date, Action ("Inspect").
  - Clicking any row loads that case's timeline and details instantly into view.

---

## 4. Verification & Acceptance Criteria
- [ ] Entering a valid tracking code retrieves case status, timeline, and public notes.
- [ ] Entering an invalid or non-existent code shows a clean "Case Not Found" error banner.
- [ ] "My Submitted Cases" correctly lists the authenticated employee's submissions via `GET /feedback/my`.
- [ ] Private investigator notes (`isPublicToComplainant: false`) are never leaked or displayed.
- [ ] 0 Oxlint errors, 0 warnings, and 0 `prop-types` imports.
