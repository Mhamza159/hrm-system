# Plan 34-02: Backend REST APIs, User Access Service, Scoped PBAC, Pagination, Security Actions, Audit Log & Notification Integration

**Phase**: 34 — User Access Module Overhaul  
**Status**: Planned  
**Layer**: Backend Routes, Controllers, Services & Middleware  
**Estimated Complexity**: High  

---

## 1. Goal
Implement a dedicated backend service layer (`user.service.js`) and RESTful controller architecture supporting high-performance paginated listings, deep employee population, aggregated KPI statistics, granular PBAC scoping, administrative account security operations (unlock, session revocation, force password change), and end-to-end audit log & notification dispatch.

---

## 2. Requirements & Scope

1. **User Access Service (`backend/src/modules/users/user.service.js`)**:
   - `getUsers(query, actor)`:
     - Implements pagination (`page`, `limit`), sorting, and multi-field search (`name`, `email`, `employeeCode`).
     - Supports filters: `roleId`, `departmentId`, `status` (`'active' | 'inactive' | 'locked'`), `accessStatus` (`'assigned' | 'unassigned'`), `twoFactorEnabled`.
     - Deeply populates `employeeId` (selecting `name`, `employeeCode`, `departmentId`, `designationId`, `employmentStatus`, `avatar`) and `roles` (`name`, `description`, `isSystem`).
     - Enforces PBAC scoping: Super Admin / HR Manager gets organization-wide access; Department Manager gets users belonging to their department.
     - Returns `{ users, total, page, limit, totalPages }`.
   - `getUserStats(actor)`:
     - Aggregates counters: Total Users, Active Users, Inactive Users, Locked Accounts, Users with Assigned Roles, Users without Roles, 2FA Enabled count.
     - Computes distributions: Users by Role breakdown and Account Status distribution.
     - PBAC-scoped according to actor privileges.
   - `getUserById(id, actor)`:
     - Retrieves deep user profile with linked employee credentials, assigned roles, account security state, and recent activity.
     - Enforces PBAC scope guard.
   - `unlockUserAccount(id, { reason }, actor)`:
     - Clears `lockUntil` and resets `failedAttempts = 0`.
     - Logs audit record `USER_UNLOCK` with reason.
     - Emits notification and Socket.io event.
   - `revokeUserSessions(id, { reason }, actor)`:
     - Sets `refreshTokenHash = null`, invalidating active refresh token cycles immediately.
     - Logs audit record `USER_SESSIONS_REVOKED`.
   - `forcePasswordChange(id, { reason }, actor)`:
     - Sets `mustChangePassword = true`.
     - Logs audit record `USER_FORCE_PASSWORD_CHANGE`.

2. **Controller & Route Layer (`user.controller.js` & `user.routes.js`)**:
   - Standardize `ApiResponse` envelope: `data: users` (array) and `meta: { total, page, limit, totalPages }` for full backward compatibility.
   - `GET /api/v1/users/stats` -> `userController.getUserStats`
   - `GET /api/v1/users` -> `userController.getUsers`
   - `GET /api/v1/users/:id` -> `userController.getUserById`
   - `POST /api/v1/users/:id/unlock` -> `userController.unlockUserAccount`
   - `POST /api/v1/users/:id/revoke-sessions` -> `userController.revokeUserSessions`
   - `POST /api/v1/users/:id/force-password-change` -> `userController.forcePasswordChange`
   - Register `user.view` permission in `permissions.js` and `roles.seed.js`.

3. **Audit Log & Notification Integrations**:
   - Capture `AuditService.log` on status mutations, role reassignments, account unlocks, and session revocations.
   - Dispatch real-time Socket.io and in-app notifications for security events.
