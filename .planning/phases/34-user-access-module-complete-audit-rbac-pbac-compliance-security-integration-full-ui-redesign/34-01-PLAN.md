# Plan 34-01: Data Model Alignment, User Schema Extension (`name`), User Status State Machine & Security Action Engine

**Phase**: 34 — User Access Module Overhaul  
**Status**: Planned  
**Layer**: Database Models & Core Utilities  
**Estimated Complexity**: Moderate  

---

## 1. Goal
Extend the `User` Mongoose schema with first-class `name` attribute, user account status state machine (handling `isActive`, `lockUntil`, `failedAttempts`, `mustChangePassword`, and `twoFactorEnabled`), and build atomic backend utility methods for security operations (unlocking accounts, revoking active sessions, forcing password changes, and syncing names with linked `Employee` records).

---

## 2. Requirements & Scope

1. **User Schema Extension (`backend/src/models/user.model.js`)**:
   - Add `name`: `{ type: String, trim: true, default: '' }` with text search index support.
   - Compound indexes: `{ isActive: 1, isDeleted: 1 }`, `{ lockUntil: 1 }`, `{ email: 1 }`, `{ employeeId: 1 }`, `{ roles: 1 }`.
   - Ensure virtual or method for `isLocked`: `() => Boolean(this.lockUntil && this.lockUntil > new Date())`.
   - Ensure virtual or method for `accountStatus`: `'locked' | 'inactive' | 'active'`.

2. **Validation Schemas (`backend/src/modules/users/user.validation.js` or `auth.validation.js`)**:
   - `getUsersQuerySchema`: Pagination (`page`, `limit`), `search`, `roleId`, `departmentId`, `status` (`'all' | 'active' | 'inactive' | 'locked'`), `accessStatus` (`'all' | 'assigned' | 'unassigned'`), `has2fa`.
   - `unlockUserSchema`: Validation for target user ID and optional administrative reason.
   - `revokeSessionsSchema`: Validation for target user ID and mandatory reason.
   - `forcePasswordChangeSchema`: Validation for target user ID.

3. **Employee-User Synchronization Hooks**:
   - Ensure employee onboarding (`employee.service.js`) populates `user.name = employee.name`.
   - Ensure employee profile update and change requests update `user.name` when employee name changes.

---

## 3. Implementation Steps

1. Update `backend/src/models/user.model.js`:
   - Add `name` field.
   - Add virtual `isLocked` and helper method `toSafeObject()`.
2. Create/update validation schemas in `backend/src/modules/users/user.validation.js`:
   - Define query parameters validation for paginated users explorer.
   - Define payload validation for unlock, session revocation, and status mutations.
3. Verify backward compatibility: ensure all existing auth, employee, and role tests continue passing.

---

## 4. Verification & Testing
- Unit test verification in `backend/tests/userAccess.module.overhaul.test.js` covering schema validations, `isLocked` calculation, and employee-user name synchronization.
