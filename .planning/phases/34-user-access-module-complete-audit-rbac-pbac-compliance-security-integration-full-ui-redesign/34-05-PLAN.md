# Plan 34-05: Forensic User Inspect Modal (Identity, Roles, Effective Permissions Matrix, Security State & Audit Timeline)

**Phase**: 34 — User Access Module Overhaul  
**Status**: Planned  
**Layer**: Frontend Forensic Inspection UI  
**Estimated Complexity**: High  

---

## 1. Goal
Design and construct a comprehensive 5-tab forensic inspection modal (`UserInspectModal.jsx`) providing complete visibility into user identity, linked employee coordinates, assigned roles, effective compiled permissions matrix, account security & session posture, and access history timeline.

---

## 2. Requirements & Scope

1. **Header & User Summary Banner**:
   - Prominent user avatar, full name, email, employee code, active status badge, and role pills.
   - Quick header actions: Refresh details, Close modal.

2. **Tab 1: User Identity & Linked Employee**:
   - Detailed user account metadata (`User ID`, `Email`, `Username`, `Created Date`, `Last Modified`).
   - Linked employee master credentials (`Employee Code`, `Department`, `Designation`, `Employment Status`, `Work Email`, `Phone Number`, `Joining Date`).
   - Graceful fallback when user is a standalone administrative user without a linked employee record.

3. **Tab 2: Assigned Roles & Scope**:
   - Cards for every assigned role detailing role title, system vs custom role indicator, description, and assignment details.
   - Privilege hierarchy badge (e.g., Super Admin, High Privilege, Standard).

4. **Tab 3: Effective Permissions Matrix**:
   - Deep inspection of the user's compiled permissions (fetched from `GET /api/v1/users/:id/effective-permissions`).
   - Permissions grouped by module (Authentication, Employees, Attendance, Leaves, Payroll, Roles, Audit, Settings).
   - Display action identifier, human-readable label, description, and PBAC scope badge (`all`, `department`, `team`, `own`).
   - Clear distinction between role-derived permissions and explicit admin privileges.

5. **Tab 4: Account Security & Session Management**:
   - Current authentication posture:
     - Account Status: Active vs Deactivated.
     - Brute-Force Defense: Failed login attempts counter (`failedAttempts`) and Lockout status (`lockUntil`).
     - Session Token Status: Active session indicator (refresh token present/revoked).
     - Two-Factor Authentication (2FA): Enabled/Disabled badge.
     - First Login Mandate: `mustChangePassword` flag status.
     - QR Code Hardware Binding: Bound device model, device ID, and binding timestamp.
   - Inline Action Triggers: "Unlock Account", "Revoke Sessions", "Reset Device Binding", "Force Password Change".

6. **Tab 5: Access & Audit History**:
   - Chronological audit trail showing past role assignments, status modifications, emergency password resets, and recent logins.
   - Display timestamp, actor identity, action type, and note/reason.

---

## 3. Implementation Steps

1. Create `frontend/src/features/users/components/user-access/UserInspectModal.jsx`.
2. Connect RTK Query hooks `useGetUserByIdQuery` and `useGetEffectivePermissionsQuery`.
3. Support direct action transitions (e.g. clicking "Unlock Account" or "Assign Roles" from inside the inspect modal).
