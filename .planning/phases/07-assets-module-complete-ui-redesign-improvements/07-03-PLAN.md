# Plan 07-03: Assets Register (Active & Archive Tabs) & Requisitions Workflow

## Objective
Overhaul `AssetsPage.jsx` into a dual Active/Archive lifecycle console with strict assignment deletion blocking, and redesign `AssetRequestsPage.jsx` from scratch into an executive requisition workflow with modern action modals.

---

## Tasks

### Task 1: Wire RTK Query API for Restore and Permanent Delete
- In [`frontend/src/features/assets/assetApi.js`](file:///c:/Users/hamih/OneDrive/Desktop/AtoZ%20Coder/Advanced%20MERN/HRM/frontend/src/features/assets/assetApi.js):
  - Add `restoreAsset: builder.mutation({ url: '/assets/:id/restore', method: 'POST', invalidatesTags: ['Asset'] })`.
  - Add `permanentDeleteAsset: builder.mutation({ url: '/assets/:id/permanent', method: 'DELETE', invalidatesTags: ['Asset'] })`.
  - Ensure `getAssets` query parameters pass `archived` boolean properly.

### Task 2: Redesign Assets Register Page (`AssetsPage.jsx`)
- In [`frontend/src/features/assets/pages/AssetsPage.jsx`](file:///c:/Users/hamih/OneDrive/Desktop/AtoZ%20Coder/Advanced%20MERN/HRM/frontend/src/features/assets/pages/AssetsPage.jsx):
  - **Tabs Bar**:
    - **Active Tab** (with live active count badge).
    - **Archive Tab** (with live archived count badge).
  - **Unified Toolbar**:
    - Single search input (Tag, Name, Serial Number, Custodian).
    - Type filter (Laptop, Desktop, Monitor, etc.).
    - Status filter (Available, Assigned, Under Repair, Retired).
    - Expiring Soon checkbox toggle.
    - "Add Asset" button guarded by `<Can I="create" a="Asset">`.
  - **Active Tab Data Table**:
    - Columns: Asset Tag & Name, Type & Model, Serial Number (`font-mono`), Custodian (`PersonRow` or "Unassigned" pill), Status badge, Warranty chip, Actions.
    - Row-click opens `AssetDetailModal`.
    - Inline Actions:
      - Assign Custodian (if status available).
      - Return to Inventory (if status assigned).
      - Edit Asset.
      - **Delete Asset**:
        - **Critical Guard**: If `asset.status === 'assigned' || asset.assignedTo`, the delete action is disabled/locked with a tooltip or badge: `"Assigned to [Name] — Return before deleting"`.
        - If available, triggers `ConfirmDialog` (replacing native `window.confirm`).
  - **Archive Tab Data Table & Modal**:
    - Shows archived records with archive timestamps and previous details.
    - Row-click opens Archive Asset Detail Modal displaying:
      - Warning banner explaining asset is decommissioned.
      - If assigned: amber banner warning that deletion is prohibited.
      - **Revert to Active** CTA (`restoreAsset` mutation).
      - **Permanent Delete** CTA (`permanentDeleteAsset` mutation with double confirmation).
      - If assigned, Permanent Delete CTA is disabled with explicit warning.

### Task 3: Redesign Asset Requisitions Page (`AssetRequestsPage.jsx`)
- In [`frontend/src/features/assets/pages/AssetRequestsPage.jsx`](file:///c:/Users/hamih/OneDrive/Desktop/AtoZ%20Coder/Advanced%20MERN/HRM/frontend/src/features/assets/pages/AssetRequestsPage.jsx):
  - Redesign from scratch with unified header, KPI metric counters (Pending Review, Approved, Allocated, Rejected).
  - Status filter pill tabs: `All Requisitions`, `Pending Review`, `Approved`, `Allocated`, `Rejected`.
  - Semantic enterprise data table:
    - Requester (`PersonRow` with avatar, name, department, employee code).
    - Requested Category/Asset with icon.
    - Business Justification & Required By Date.
    - Priority / Urgency badge (`High`, `Medium`, `Low`).
    - Decision Status pill.
    - Actions.
  - Action Modals:
    - **Approve Requisition Modal**: Review notes, approval trigger.
    - **Allocate Asset Modal**: Replaced raw select with searchable available equipment cards.
    - **Reject Requisition Modal**: Mandatory rejection justification.
  - PBAC & RBAC: Wrap all approval/rejection/allocation triggers in `<Can I="manage" a="Asset">`. If permission is absent, hide actions completely.
