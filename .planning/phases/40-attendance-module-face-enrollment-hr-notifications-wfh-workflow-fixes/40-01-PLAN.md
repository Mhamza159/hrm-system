# Plan 40-01: Face Punch Validation & Face Enrollment Required Modal

**Phase:** Phase 40: Attendance Module — Face Enrollment, HR Notifications & WFH Workflow Fixes  
**Plan ID:** 40-01  
**Target:** Face Punch Backend Security Guard & Frontend Enrollment-Required Modal  
**Requirement Reference:** Section 1 ("Face Punch Without Face Enrollment — Mandatory Validation")

---

## 1. Goal & Objectives
Ensure that an employee who has NOT completed Face Enrollment or whose enrollment is not approved (`status !== 'approved'`) can NEVER perform attendance punch via Face Punch.
- **Backend:** Enforce a strict server-side validation guard in `checkIn` and `verifyFacePunch` that rejects face punch attempts from un-enrolled users with a structured error payload (`code: 'FACE_ENROLLMENT_REQUIRED'`), creating no attendance record and preventing any presence mark.
- **Frontend:** Implement an elegant, centered **"Face Enrollment Required"** modal dialog conforming to the Elvara Forest design system. If the employee attempts Face Punch without an approved enrollment, block camera activation and display this modal, guiding them to complete Face Enrollment or cancel.

---

## 2. File Level Changes

### 1. `backend/src/modules/attendance/attendance.service.js`
- In `checkIn`: When `source === 'face'` or when `liveDescriptor` is submitted, inspect the authenticated user's `faceEnrollment` status before any attendance record creation or punch processing.
- In `verifyFacePunch`:
  - If `!dbUser.faceEnrollment || dbUser.faceEnrollment.status !== 'approved' || !dbUser.faceEnrollment.descriptors?.length`:
    - Throw `new ApiError(400, 'Face enrollment is required before using Face Punch. Please complete Face Enrollment and await approval.', [{ code: 'FACE_ENROLLMENT_REQUIRED', status: dbUser?.faceEnrollment?.status || 'none' }])`.
  - Ensure direct API requests sending `source: 'face'` without `liveDescriptor` are also caught by this guard before any default processing occurs.
  - Log an audit trail entry for `FACE_PUNCH_BLOCKED_UNENROLLED`.

### 2. `frontend/src/features/attendance/components/FaceEnrollmentRequiredModal.jsx` (New Component)
- Create a reusable, centered modal dialog:
  - **Title:** `Face Enrollment Required`
  - **Icon:** `ScanFace` with amber/emerald accent ring
  - **Message:** `"Your face has not been enrolled yet. Please complete Face Enrollment before using Face Punch."`
  - **Actions:**
    - Primary Button: `"Complete Face Enrollment"` (navigates to `/attendance/face-enrollment` or triggers enrollment flow)
    - Secondary Button: `"Cancel"` (closes modal)
  - Follow universal modal tokens: `fixed inset-0 z-[100] flex items-center justify-center p-4 bg-black/15 backdrop-blur-xs`, `rounded-2xl max-w-md w-full bg-white dark:bg-[#111D17] border border-slate-200 dark:border-[#1A3125] shadow-2xl`.

### 3. `frontend/src/features/attendance/components/FaceCheckInModal.jsx`
- Check `enrollmentStatus` immediately upon `isOpen`.
- If `enrollmentStatus !== 'approved'`:
  - Suppress camera acquisition (`startCamera` must not run).
  - Do not mount the neural vision preloader.
  - Render `FaceEnrollmentRequiredModal` (or show the enrollment-required view directly inside the modal with the specified actions).
- Handle backend `FACE_ENROLLMENT_REQUIRED` error gracefully by displaying the modal if the API returns that code.

### 4. `frontend/src/features/attendance/components/PunchCardWidget.jsx` & `MyAttendancePage.jsx`
- Pass enrollment status or open `FaceEnrollmentRequiredModal` if employee clicks the Face Punch trigger without enrollment.

---

## 3. Verification Criteria
1. Employee with `faceEnrollment.status: 'none'` attempts Face Punch $\rightarrow$ Camera does not turn on; "Face Enrollment Required" modal appears.
2. Clicking "Complete Face Enrollment" redirects to the face enrollment view.
3. Employee with `faceEnrollment.status: 'pending'` $\rightarrow$ Face Punch blocked with clear modal stating approval is pending.
4. Direct `POST /api/v1/attendance/check-in` with `source: 'face'` $\rightarrow$ Returns HTTP 400 with `code: 'FACE_ENROLLMENT_REQUIRED'`, zero attendance record created in MongoDB.
