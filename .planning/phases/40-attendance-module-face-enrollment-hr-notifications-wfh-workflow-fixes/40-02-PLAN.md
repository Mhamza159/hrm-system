# Plan 40-02: Face Enrollment HR Notification Flow & Recipient Resolution

**Phase:** Phase 40: Attendance Module — Face Enrollment, HR Notifications & WFH Workflow Fixes  
**Plan ID:** 40-02  
**Target:** Face Enrollment Notification Dispatch, HR Recipient Resolution & Audit Logging  
**Requirement Reference:** Section 2 ("Face Enrollment — HR Notification Not Triggered")

---

## 1. Goal & Objectives
Ensure that whenever an employee successfully completes Face Enrollment:
- The backend triggers an authoritative notification to all authorized HR Managers and Super Admins.
- The notification contains clear context: Employee Name, Employee Code, enrollment timestamp, and status.
- The notification links directly to the HR Face Enrollment review table (`/attendance/face-enrollments`).
- Sensitive biometric vectors, raw face descriptors, and base64 strings are strictly excluded from notifications.
- Failed enrollments (e.g. biometric collision) do NOT generate success notifications.
- Notifications appear in the HR notification bell/drawer, update the unread count, and emit in real-time over Socket.io.

---

## 2. File Level Changes

### 1. `backend/src/modules/attendance/attendance.service.js`
- In `enrollFace(userId, { descriptors, photo })`:
  - After `user.save()` completes successfully:
    - Retrieve applicant's employee details (`Employee.findOne({ userId: user._id })`).
    - Resolve authorized HR recipients via helper `resolveHRAndAdminRecipients()`.
    - Dispatch notification via `notify(recipientIds, { ... })`:
      - `type: 'attendance'`
      - `module: 'attendance'`
      - `priority: 'normal'`
      - `title: 'Face Enrollment Completed'`
      - `body: `${applicantName} (${applicantCode}) has successfully completed Face Enrollment and their enrollment record is available for review.``
      - `link: '/attendance/face-enrollments'`
      - `metadata: { employeeId, userId: user._id, type: 'face_enrollment', status: 'pending' }`
    - Await or handle the notification promise safely, logging an explicit warning if delivery fails.
  - Record audit log: `FACE_ENROLLMENT_SUBMITTED_NOTIFIED`.

### 2. Recipient Resolution Helper (`resolveHRAndAdminRecipients`)
- Ensure both Role ObjectIds (`Super Admin`, `HR Manager`) and fallback legacy strings are queried:
  ```javascript
  const adminRoles = await Role.find({ name: { $in: ['Super Admin', 'HR Manager'] } }, '_id').lean();
  const adminRoleIds = adminRoles.map((r) => r._id);
  const adminUsers = await User.find({
    $or: [
      { roles: { $in: adminRoleIds } },
      { role: { $in: ['Super Admin', 'HR Manager'] } }
    ],
    isActive: true,
    isDeleted: { $ne: true }
  }, '_id').lean();
  ```
- Exclude the applicant themselves from receiving the notification if they happen to possess an admin role.

### 3. Biometric Security & Data Protection Guard
- Strictly verify that no descriptor floats, embeddings, or facial image buffers are passed in notification metadata or message text.

---

## 3. Verification Criteria
1. Employee submits valid face enrollment photos $\rightarrow$ Enrollment saved as `pending`.
2. Notification is generated in `Notification` collection for every active HR Manager and Super Admin.
3. HR notification drawer displays `"Face Enrollment Completed: [Employee Name] has successfully completed Face Enrollment..."`.
4. Clicking notification navigates to `/attendance/face-enrollments`.
5. Biometric collision rejection $\rightarrow$ 0 notifications generated.
