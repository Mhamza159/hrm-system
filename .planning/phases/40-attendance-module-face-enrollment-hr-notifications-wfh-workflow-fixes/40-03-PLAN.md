# Plan 40-03: Work From Home (WFH) One-Day-Before Advance Notice Restriction

**Phase:** Phase 40: Attendance Module — Face Enrollment, HR Notifications & WFH Workflow Fixes  
**Plan ID:** 40-03  
**Target:** WFH Advance-Notice Business Rule Enforcement (Frontend & Backend)  
**Requirement Reference:** Section 3 ("Work From Home (WFH) — One-Day-Before Application Restriction")

---

## 1. Goal & Objectives
Enforce the mandatory business requirement that Work From Home (WFH) applications must be submitted **at least one day before** the requested WFH date, based on the organization's official timezone (`Asia/Karachi`).
- Applying for WFH on the **same day** (e.g. applying Tuesday for Tuesday) must be strictly **rejected**.
- Applying for **past dates** must be strictly **rejected**.
- Applying for **tomorrow or future dates** (subject to standard WFH limits) is **allowed**.
- Validation must be synchronized between client-side UX (date picker `min` constraint & real-time error banner) and server-side authorization (Zod schema & `applyWFH` service guard).

---

## 2. File Level Changes

### 1. `backend/src/modules/attendance/attendance.service.js`
- In `applyWFH({ user, date, reason })`:
  - Calculate today's date and tomorrow's date at midnight in `Asia/Karachi`:
    ```javascript
    const timeZone = 'Asia/Karachi';
    const nowInKarachi = new Date(new Date().toLocaleString('en-US', { timeZone }));
    const tomorrowKarachi = new Date(nowInKarachi);
    tomorrowKarachi.setDate(tomorrowKarachi.getDate() + 1);
    tomorrowKarachi.setHours(0, 0, 0, 0);

    const targetDate = normalizeToUtcMidnight(new Date(date));
    const targetDateKarachi = new Date(new Date(date).toLocaleString('en-US', { timeZone }));
    targetDateKarachi.setHours(0, 0, 0, 0);

    if (targetDateKarachi.getTime() < tomorrowKarachi.getTime()) {
      throw new ApiError(
        400,
        'WFH applications must be submitted at least one day before the requested date. Same-day applications are not allowed.',
        [{ code: 'WFH_ADVANCE_NOTICE_REQUIRED', minAllowedDate: tomorrowKarachi.toISOString().split('T')[0] }]
      );
    }
    ```
  - Record audit log on rejection if attempt is flagged.

### 2. `backend/src/modules/attendance/attendance.validation.js`
- In `wfhRequestSchema`:
  - Add refinement or doc comments clarifying that `date` must represent a future date at least 24 hours / next day in `Asia/Karachi`.

### 3. `frontend/src/features/attendance/components/ApplyWFHModal.jsx`
- Compute `tomorrowStr` on initialization:
  ```javascript
  const getTomorrowString = () => {
    const d = new Date();
    d.setDate(d.getDate() + 1);
    return d.toISOString().split('T')[0];
  };
  ```
- Initialize `date` state to `getTomorrowString()` instead of today's date.
- Set `<input type="date" min={getTomorrowString()} ... />` to prevent selecting today or past dates in the native date-picker.
- Add client-side validation in `handleSubmit`:
  ```javascript
  const selectedDate = new Date(date);
  const tomorrow = new Date(getTomorrowString());
  if (selectedDate < tomorrow) {
    setErrorMessage('WFH applications must be submitted at least one day before the requested date. Same-day applications are not allowed.');
    return;
  }
  ```
- Render a clear, helpful policy reminder under the date input:
  `"Notice: WFH must be requested at least 1 day in advance. Same-day applications cannot be processed."`

## 3. Verification Criteria
1. User selects today's date in `ApplyWFHModal` $\rightarrow$ Datepicker prevents selection or form shows error: `"WFH applications must be submitted at least one day before the requested date. Same-day applications are not allowed."`.
2. Direct API request with today's date (`POST /attendance/wfh` with `date: today`) $\rightarrow$ HTTP 400 with `code: 'WFH_ADVANCE_NOTICE_REQUIRED'`.
3. Direct API request with yesterday's date $\rightarrow$ HTTP 400.
4. User selects tomorrow or a date 3 days in advance $\rightarrow$ Application submits successfully (HTTP 201/200).
