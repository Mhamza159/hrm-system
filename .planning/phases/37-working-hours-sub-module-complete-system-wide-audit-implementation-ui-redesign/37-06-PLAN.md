# Plan 37-06: Payroll Engine Working Days Integration & Historical Snapshot Protection

## Objective
Harmonize the Payroll Module with the Working Hours configuration so that scheduled working days in a pay cycle are computed dynamically from active working schedules and gazetted holidays. Guarantee that non-working weekly offs are never penalized as unexcused absences, and strictly protect historical finalized/approved payroll records from retroactive recalculation.

---

## Technical Context
- **Files Touched**:
  - `backend/src/modules/payroll/payrollProcessor.js`
  - `backend/src/modules/payroll/payroll.service.js`
  - `backend/src/models/payslip.model.js`
- **Dependencies**: `SettingService`, `workdayHelper.js`, `Attendance` model, `Holiday` model.

---

## Detailed Implementation Steps

1. **Dynamic Working Days in Pay Cycle (`payrollProcessor.js`)**:
   - For each employee in the payroll run:
     - Resolve `effectiveWorkDays = getEffectiveWorkDays(emp.shiftId, companyWorkingDays)` via `workdayHelper.js`.
     - Calculate total scheduled working days in the month/cycle using `calculateWorkingDaysInMonth(year, month, effectiveWorkDays, holidayDatesSet)`.
     - In `attendanceSummary`:
       - Replace hardcoded `workingDays: 30` with `scheduledWorkingDays` (e.g. 21, 22, or 26 depending on 5-day or 6-day week).
       - Maintain standard Pakistani 30-day salary divisor for daily salary calculations (`grossSalary / 30`) per labour law, but store accurate `scheduledWorkingDays` in payslip metadata.

2. **Unexcused Absence Integrity**:
   - Ensure unexcused absences only count days that were scheduled working days according to the employee's effective schedule and not gazetted holidays or weekly offs.
   - Guard: weekly offs (`status: 'weekly_off'`) must NEVER contribute to `unexcusedAbsenceDays` or trigger salary deductions.

3. **Historical Finalized Record Protection**:
   - Enforce invariant: Once a payroll run is in `approved` or `paid` state, its `attendanceSummary`, `earnings`, `deductions`, and `netPayPaisa` are immutable snapshots.
   - When an administrator modifies Working Hours settings in Phase 37, already finalized/processed historical payroll runs MUST NOT be recomputed.
   - Setting changes take effect only for subsequent draft payroll generations.

---

## Verification Criteria
- [ ] Payslip `attendanceSummary.workingDays` reflects true scheduled working days of the period.
- [ ] Weekly off days without punches cause 0 salary deduction.
- [ ] Approved/paid historical payslips remain unchanged after working days settings are modified.
