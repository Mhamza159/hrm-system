# Plan 32-01: Deep Backend Actor Enrichment & Historical Attribution Pipeline

## Objective
Enhance the backend query pipeline in `backend/src/modules/audit/audit.service.js` to deeply populate actor identity (User -> Employee -> Department, Designation, Roles) and implement an actor normalization transformer that safely guarantees complete, high-fidelity actor attributes for every audit log record without breaking existing contracts or leaking sensitive data.

---

## Proposed Changes

### 1. Backend Service Deep Population (`backend/src/modules/audit/audit.service.js`)
- Update `queryAuditLogs` and `getAuditLogById` to perform two-level deep population:
  ```javascript
  .populate({
    path: 'actorId',
    select: 'email avatar isActive roles employeeId',
    populate: [
      { path: 'roles', select: 'name label' },
      {
        path: 'employeeId',
        select: 'name employeeCode avatar departmentId designationId status',
        populate: [
          { path: 'departmentId', select: 'name code' },
          { path: 'designationId', select: 'title titleUrdu grade' }
        ]
      }
    ]
  })
  ```
- Build an actor formatting utility `normalizeAuditActor(log)`:
  - If `log.actorId` is populated with `employeeId`:
    - `name`: `log.actorId.employeeId.name`
    - `avatar`: `log.actorId.employeeId.avatar || log.actorId.avatar || null`
    - `employeeCode`: `log.actorId.employeeId.employeeCode`
    - `email`: `log.actorId.email || log.actorEmail`
    - `role`: `log.actorId.roles?.[0]?.name || log.actorRole`
    - `designation`: `log.actorId.employeeId.designationId?.title || 'Staff'`
    - `department`: `log.actorId.employeeId.departmentId?.name || 'General'`
    - `accountStatus`: `log.actorId.isActive ? 'Active' : 'Inactive'`
    - `employmentStatus`: `log.actorId.employeeId.status || 'Active'`
  - If `log.actorId` is a standalone user without employee:
    - `name`: User email username prefix or `log.actorEmail`
    - `avatar`: `log.actorId.avatar || null`
    - `employeeCode`: 'N/A'
    - `role`: `log.actorId.roles?.[0]?.name || log.actorRole`
    - `designation`: 'System Administrator'
    - `department`: 'Administration'
    - `accountStatus`: `log.actorId.isActive ? 'Active' : 'Inactive'`
  - If `log.actorId` is null (automated cron/system job):
    - `name`: 'System Automation Engine'
    - `avatar`: null
    - `employeeCode`: 'SYS-CRON'
    - `role`: 'SYSTEM'
    - `designation`: 'Background Daemon'
    - `department`: 'Kernel & Infrastructure'
    - `accountStatus`: 'Active'
- Attach the normalized `actor` object to each audit item in `queryAuditLogs` and `getAuditLogById` while preserving original `actorId`, `actorEmail`, and `actorRole` fields for complete backward compatibility.

  2. Standalone admin user without employee populates gracefully with fallback attributes.
  3. System / null actor logs return proper automated daemon attributes.
  4. Single log forensic query (`getAuditLogById`) returns complete populated actor.
