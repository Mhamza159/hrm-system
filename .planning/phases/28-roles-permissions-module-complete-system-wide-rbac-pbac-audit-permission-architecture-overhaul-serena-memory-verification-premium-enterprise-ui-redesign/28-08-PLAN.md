# Plan 28-08: System-Wide UI Permission Guarding Audit (Sidebar, Pages, Action Buttons & CASL Can)

## Goal
Audit every module across the entire HRMS frontend application to guarantee that unauthorized functionality is NEVER displayed to users. Eliminate all hardcoded role checks (e.g. `user.role === 'Admin'`), standardizing 100% of UI conditional rendering onto `usePermission()` and `<Can>`. Ensure that navigation links in `Sidebar.jsx`, page-level action headers (Create, Export, Import, Bulk Actions), table row action buttons (Edit, Delete, Archive, Restore), and modal triggers are strictly hidden when the user lacks the required permission.

## Target Files
- `frontend/src/components/layout/Sidebar.jsx`
- `frontend/src/components/common/Can.jsx`
- `frontend/src/hooks/usePermission.js`
- `frontend/src/lib/ability.js`
- Core Module Pages:

  - `frontend/src/features/settings/pages/CompanySettingsPage.jsx`
  - `frontend/src/features/roles/pages/RolesListPage.jsx`

## Audit Criteria Across All Modules
1. **Navigation & Sidebar (`Sidebar.jsx`)**:
   - Every sidebar route item must declare its required permission key (e.g. `role.view`, `employee.view`, `attendance.view`, `leave.view`, `payroll.view`, `settings.view`).
   - If user ability lacks the permission, the menu item and its badge must NOT render in the sidebar.
2. **Page-Level Mutation Actions**:
   - "Add Employee", "Create Department", "New Shift", "Run Payroll", "Create Role", "Apply Policy" must be wrapped in `<Can I="create" this="Employee">` or `can('employee.create')`.
   - If user only has `view` rights, the page displays records in read-only mode with zero create/import buttons.
3. **Table Row Context Actions**:
   - `Edit` button wrapped in `can('module.edit')`.
   - `Delete` button wrapped in `can('module.delete')`.
   - `Archive` button wrapped in `can('module.manage')`.
   - `Restore` button wrapped in `can('module.manage')`.
   - If user has no mutation permissions, action columns must either omit unauthorized buttons or hide the action column completely.
4. **Detail Pages & Confidential Fields**:
   - Employee salary information and banking tabs are wrapped in `can('employee.salary.view')`.
   - Attendance correction approvals wrapped in `can('attendance.approve')`.
   - Leave status decision dialogs wrapped in `can('leave.approve')`.

## Detailed Implementation Tasks
- [ ] **Task 1: Sidebar Permission Guarding Audit (`Sidebar.jsx`)**:
  - Audit every menu item in `navigationConfig.js` / `Sidebar.jsx`.
  - Ensure every item evaluates `usePermission().can(...)`.
  - Test with all 4 system roles: confirm `Employee` sees only self-service items; `Department Manager` sees team items; `HR Manager` sees workforce items; `Super Admin` sees full navigation.
- [ ] **Task 2: Standardization of `<Can>` and `usePermission`**:
  - Audit `frontend/src/components/common/Can.jsx` to support both CASL syntax (`I="action" this="subject"`) and direct permission strings (`perform="employee.create"`).
  - Ensure additive permission union in `buildAbilityFromRules` properly reconciles multiple user roles and active delegations.
- [ ] **Task 3: Cross-Module Component Audit & Cleanup**:
  - Search codebase for any lingering `role === 'admin'` or `user?.role === 'Super Admin'` checks and replace them with permission-based checks (`can('permission.name')`).
  - Audit action buttons across Departments, Designations, Shifts, Employees, Attendance, Leaves, and Payroll pages.
- [ ] **Task 4: Route Guards Verification (`ProtectedRoute.jsx`)**:
  - Verify that unauthorized URL navigation (e.g. Employee typing `/roles` or `/payroll` in the browser bar) is intercepted immediately by `ProtectedRoute` and redirected to an unauthorized screen or dashboard with a friendly error toast.

## Verification & Acceptance Criteria
- Logging in as `Employee`: Zero administrative buttons (Create, Edit, Delete, Archive, Settings) appear anywhere across the entire UI.
- Logging in as `Department Manager`: Manager sees team review actions but zero company-wide settings or master payroll execution controls.
- Attempting to force-visit unauthorized URLs routes cleanly to 403 or dashboard without console crashes.
- Zero hardcoded role checks remain in page components.
