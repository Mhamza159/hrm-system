# Plan 28-03: System-Wide PBAC Policy Evaluation, Data Scoping Engine & Field-Level Masking

## Goal
Audit, harden, and systematically enforce Policy-Based Access Control (PBAC) across all backend services. Standardize `backend/src/utils/scopeFilter.js` and `backend/src/utils/fieldFilter.js` to ensure that data scopes (`own`, `team`, `department`, `all`) and confidential field masking (`salary`, `cnic`, `bankAccount`) are enforced directly inside database queries and serialization logic, guaranteeing that unauthorized records are NEVER leaked over the wire.

## PBAC Data Scoping Model (`docs/FRD.md` Section 3 & `docs/TECH-SPEC.md` Section 6)
- **`all` Scope (Priority 4)**:
  - Accessible by `Super Admin` and `HR Manager`.
  - Unrestricted query filter: `{}` (all records across company).
- **`department` Scope (Priority 3)**:
  - Accessible by Department Heads and Division Coordinators.
  - Query filter: `{ departmentId: user.departmentId }`. Fail-safe fallback to own records if user lacks department assignment.
- **`team` Scope (Priority 2)**:
  - Accessible by Department Managers and Project Leads.
  - Query filter: `{ $or: [{ managerId: user.employeeId }, { reportingManagerId: user._id }, { employeeId: { $in: teamEmployeeIds } }] }`.
  - Only direct and indirect subordinates under user's hierarchy.
- **`own` Scope (Priority 1)**:
  - Default self-service scope for all `Employee` roles.
  - Query filter: `{ employeeId: user.employeeId }` or `{ _id: user._id }`.

## Detailed Implementation Tasks
- [ ] **Task 1: Scope Generator Hardening (`scopeFilter.js`)**:
  - Support multi-entity resolution: `Employee`, `Attendance`, `Leave`, `Payroll`, `Loan`, `Expense`, `Performance`, `Asset`.
  - Ensure dynamic subordinate discovery caches team employee IDs within request context for fast O(1) `$in` queries.
  - Guard against null or undefined actor IDs: fail securely to an empty result set `{ _id: null }` rather than leaking all records.
- [ ] **Task 2: Dynamic Middleware Integration (`checkPermission.js`)**:
  - Resolve effective scope using hierarchy `all > department > team > own`.
  - Attach `req.permissionScope` and `req.ability` to the Express request object so downstream controllers and services can consume it directly without re-querying the database.
- [ ] **Task 3: Field Masking Enforcement (`fieldFilter.js`)**:
  - Define strictly protected fields: `cnic`, `bankAccount`, `basicSalary`, `grossSalary`, `netSalary`, `allowances`, `deductions`.
  - When caller lacks `employee.salary.view` or caller's scope is not `all`, strip sensitive financial details from employee and payroll objects.
  - Ensure masking replaces sensitive strings with sanitized indicators or excludes them entirely from JSON serialization.
- [ ] **Task 4: Cross-Module Service Audit**:
  - Verify `employee.service.js`: verify that `getAllEmployees` injects `buildScopeQuery(user, req.permissionScope)`.
  - Verify `attendance.service.js`: verify that team attendance and records queries apply team/department scopes.
  - Verify `leave.service.js`: verify that leave approval lists are strictly isolated to manager's direct team when role is Department Manager.
  - Verify `payroll.service.js`: verify that non-HR/non-SuperAdmin users cannot access payroll run details or salary structures.

## Verification & Acceptance Criteria
- Vitest suite `tests/rbac_pbac_role_matrix.test.js` passes with 100% green assertions.
- Department Manager direct API requests to `/api/v1/employees` only return members of their own team, with salary and CNIC fields stripped.
- Employee direct API requests to `/api/v1/attendance` only return their own check-in/out records.
- Direct tampering with query parameters (e.g. `?employeeId=OTHER_ID`) is rejected or overridden by the server-side scope filter.
