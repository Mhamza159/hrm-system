# Plan 22-03: Complete Modals Suite Redesign & Engagement Analytics

## Goal
Redesign and complete all dialogs, drawers, and modal workflows in the Announcement Module, including creation/editing with multi-department and attachment support, a rich announcement detail reader, an administrative reader analytics docket with department breakdown, and delete/archive confirmation dialogs.

## Proposed Changes

### 1. `frontend/src/features/announcements/components/AnnouncementFormModal.jsx`
- Support multi-department targeting: Select multiple departments when audience is 'department'.
- Expiry date picker with validation (`min` set to today).
- Attachments support: URL input with title and file type tag (PDF, DOCX, Image, Sheet) or file upload simulator.
- Form validation: title, content, priority, target audience, departments.
- Clear error alerts and submit loading states.
- Forest & Emerald dark/light responsive layout.

### 2. `frontend/src/features/announcements/components/AnnouncementDetailModal.jsx` (New)
- Rich inspection modal for employees and managers:
  - Formatted header with author avatar, publication date, priority badge, and target audience chips.
  - Full announcement body text with preserved paragraph spacing and readable typography.
  - Attachment list with download/view links.
  - Automatic `recordReadReceipt` mutation trigger upon opening if currently unread.
  - Action footer allowing authorized managers to jump directly to Edit or Read Analytics.

### 3. `frontend/src/features/announcements/components/ReadReceiptsModal.jsx`
- Redesign from basic list to an Executive Engagement Docket:
  - Header with announcement title and publication date.
  - 3 Summary KPI Cards:
    - **Total Target Audience**: eligible employees.
    - **Seen Count & Engagement Rate**: circular percentage gauge or badge (`e.g. 85%`).
    - **Pending Readers**: unseen employee count.
  - Department Engagement Breakdown table/bars (e.g. Engineering: 12/15 read, Sales: 8/10 read).
  - Searchable Reader Roster with employee avatar, name, department, designation, and verified read timestamp.

### 4. `frontend/src/features/announcements/components/DeleteConfirmationModal.jsx` & `ArchiveConfirmationModal.jsx` (New)
- Dedicated confirmation modals replacing raw `window.confirm`:
  - Visual danger/warning iconography.
  - Displays announcement title and code.
  - Details consequences (e.g. archiving preserves read history but hides from active feed; deletion removes from notice board).
  - Loading states during mutation execution.

## Verification Criteria
- Creating an announcement with multiple departments and attachments persists correctly to MongoDB.
- Opening an unread announcement immediately triggers `recordReadReceipt` and updates the unread badge to read.
- Read receipts modal displays correct audience count, seen count, unseen count, and department breakdown.
- Confirmation modals operate smoothly with Esc key and backdrop dismiss.
