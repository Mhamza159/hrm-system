# Plan 22-01: Backend Announcements Architecture, Archival Engine & Analytics API

## Goal
Extend the announcement schema, service, controller, routes, and validation schemas to support multi-department targeting, expiry dates, attachments, archival lifecycle (`archive` & `restore`), and comprehensive administrative read analytics with department-level breakdowns.

## Proposed Changes

### 1. `backend/src/models/announcement.model.js`
- Add `departmentIds: [{ type: mongoose.Schema.Types.ObjectId, ref: 'Department' }]` with automatic synchronization with legacy `departmentId`.
- Add `isArchived: { type: Boolean, default: false, index: true }`.
- Add `archivedAt: { type: Date, default: null }`.
- Add `archivedBy: { type: mongoose.Schema.Types.ObjectId, ref: 'User', default: null }`.
- Add `expiryDate: { type: Date, default: null }`.
- Add `attachments: [{ name: String, url: String, fileType: String, size: Number }]`.
- Update compound indexes to include `isArchived: 1` alongside `isDeleted: 1`.

### 2. `backend/src/modules/announcements/announcement.validation.js`
- Expand `createAnnouncementSchema` to accept:
  - `departmentIds`: optional array of MongoId strings.
  - `expiryDate`: optional ISO date string.
  - `attachments`: optional array of attachment objects `{ name, url, fileType, size }`.
- Expand `updateAnnouncementSchema` to accept `departmentIds`, `expiryDate`, and `attachments`.
- Expand `queryAnnouncementSchema` to support:
  - `isArchived`: boolean string (`'true' | 'false'`).
  - `departmentId`: single or comma-separated department IDs.
  - `priority`: `'low' | 'normal' | 'high' | 'urgent'`.
  - `hasRead`: boolean string (`'true' | 'false'`).
  - `sort`: `'newest' | 'oldest' | 'priority'`.

### 3. `backend/src/modules/announcements/announcement.service.js`
- Update `getAnnouncements`:
  - Handle `isArchived: query.isArchived === 'true'`. Active listings default to `isArchived: false`.
  - Filter by `departmentIds` matching user's department or provided query filter.
  - Calculate `readCount` and `hasRead` for actor.
  - Support sorting by `newest` (`createdAt: -1`), `oldest` (`createdAt: 1`), and `priority`.
- Implement `archiveAnnouncement(id, actor, scope)`:
  - Validates announcement is not already archived or deleted.
  - Sets `isArchived = true`, `archivedAt = new Date()`, `archivedBy = actor._id`, `pinned = false`.
  - Saves and returns updated announcement.
- Implement `restoreAnnouncement(id, actor, scope)`:
  - Sets `isArchived = false`, `archivedAt = null`, `archivedBy = null`.
  - Saves and returns updated announcement.
- Implement `getAnnouncementById(id, user, scope)`:
  - Returns populated announcement details.
  - If actor is an employee, automatically records a read receipt if unread.
- Enhance `getReadReceipts(id, actor, scope)`:
  - Calculate `totalTargeted`: Active employees targeted by the announcement (all active staff if company-wide; staff in `departmentIds` if department-scoped).
  - Calculate `seenCount`: Unique users who have read.
  - Calculate `unseenCount`: `totalTargeted - seenCount`.
  - Calculate `compliancePercentage`: `totalTargeted > 0 ? Math.round((seenCount / totalTargeted) * 100) : 100`.
  - Return `departmentBreakdown`: Grouped seen vs total per department.
  - Populate reader details: employee name, email, employee code, department, designation, avatar, read timestamp.

### 4. `backend/src/modules/announcements/announcement.controller.js` & `announcement.routes.js`
- Add `getAnnouncementById` (`GET /announcements/:id`).
- Add `archiveAnnouncement` (`PATCH /announcements/:id/archive`).
- Add `restoreAnnouncement` (`PATCH /announcements/:id/restore`).
- Protect archive/restore with `checkPermission('announcement.archive')` or fallback to `announcement.edit`.

## Verification Criteria
- All routes return standard envelope: `{ success: true, data: ..., pagination?: ... }`.
- Archiving an announcement removes it from active queries (`isArchived: false`) and surfaces it in archive queries (`isArchived: true`).
- Restoring an announcement preserves original `readBy` records without loss.
- 0 Oxlint warnings in `backend/src/modules/announcements`.
