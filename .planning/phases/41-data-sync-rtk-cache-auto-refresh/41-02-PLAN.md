# Plan 41-02: Comprehensive System-Wide RTK Query Mutation invalidatesTags Audit & Patching

**Phase:** Phase 41: Software-Wide Real-Time Data Synchronization, RTK Query Cache Invalidation & Automatic Refresh System  
**Plan ID:** 41-02  
**Target:** 29 Feature API Slices (`frontend/src/features/**/*Api.js`)  
**Requirement Reference:** Requirement 2 ("Software-Wide RTK Query Mutation Cache Invalidation Audit")

---

## 1. Goal & Objectives
Eliminate the issue where submitting a form, clicking a status toggle, approving/rejecting a request, or deleting an item leaves stale rows in the current table until `F5` is pressed.
- Audit all 29 API files across frontend features:
  - Attendance (`attendanceApi.js`)
  - Leaves & Holidays (`leavesApi.js`)
  - Employees (`employeesApi.js`)
  - Departments, Designations & Shifts (`departmentsApi.js`)
  - Roles & Permissions (`rolesApi.js`)
  - Payroll (`payrollApi.js`)
  - Settings & Policies (`settingsApi.js`, `policyApi.js`)
  - Assets (`assetApi.js`)
  - Expenses (`expensesApi.js`)
  - Onboarding & Offboarding (`onboardingApi.js`)
  - Performance (`performanceApi.js`)
  - Recruitment (`recruitmentApi.js`)
  - Users & Login History (`usersApi.js`, `authApi.js`)
  - Notifications & Announcements (`notificationsApi.js`, `announcementsApi.js`)
- Harmonize tag names (e.g. resolve singular vs plural inconsistencies such as `'Department'` vs `'Departments'`).
- Ensure all mutations (Create, Update, Delete, Status Change, Approve, Reject) invalidate both list tags and specific ID tags, as well as associated dashboard/summary stats tags.

---

## 2. File-Level Changes

### 1. `frontend/src/features/attendance/attendanceApi.js`
- Audit `checkIn`, `checkOut`, `applyWFH`, `decideWFH`, `applyCorrection`, `decideCorrection`, `lockMonth`:
- Ensure mutations invalidate `['Attendance', 'Team', 'WFH', 'Correction', 'AttendanceLock', 'NotificationCounts']`.

### 2. `frontend/src/features/leaves/leavesApi.js`
- Audit `applyLeave`, `decideLeave`, `cancelLeave`, `updateLeaveBalance`:
- Ensure mutations invalidate `['Leave', 'LeaveType', 'Attendance', 'NotificationCounts']`.

### 3. `frontend/src/features/employees/employeesApi.js`
- Audit `createEmployee`, `updateEmployee`, `archiveEmployee`, `restoreEmployee`, `permanentDeleteEmployee`:
- Ensure mutations invalidate `['Employee', 'Users', 'Departments', 'Designations', 'OrgChart']`.

### 4. `frontend/src/features/departments/departmentsApi.js`
- Audit Department, Designation, and Shift CRUD mutations:
- Ensure mutations invalidate both list and detail tags:
  - Department mutations: `['Departments', 'OrgChart']`.
  - Designation mutations: `['Designations', 'Departments']`.
  - Shift mutations: `['Shifts', 'Attendance']`.

### 5. `frontend/src/features/roles/rolesApi.js`
- Audit `createRole`, `updateRole`, `deleteRole`, `assignPermissions`, `delegateRole`:
- Ensure mutations invalidate `['Roles', 'RoleStats', 'RoleAnalytics', 'Permissions', 'Delegations']`.

### 6. Remaining Feature Slices (`assets`, `expenses`, `payroll`, `recruitment`, `performance`, `settings`, `onboarding`)
- Check every mutation block; replace missing or empty `invalidatesTags` with the exact provided tag types registered in `baseApi.js`.

---

## 3. Verification Criteria
1. Executing any Create/Edit/Delete or Status Change action in any module immediately updates the list view without requiring page reload.
2. Form modals close and table automatically displays the new or updated record.
3. No console tag mismatch warnings.
4. Linter passes with 0 errors; Vite production build passes cleanly.
