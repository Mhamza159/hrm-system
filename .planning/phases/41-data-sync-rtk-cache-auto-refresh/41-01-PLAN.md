# Plan 41-01: Redux Store setupListeners, BaseApi refetchOnFocus, refetchOnReconnect & Global Lifecycle Auto-Rehydration

**Phase:** Phase 41: Software-Wide Real-Time Data Synchronization, RTK Query Cache Invalidation & Automatic Refresh System  
**Plan ID:** 41-01  
**Target:** Frontend Core Networking & State Layer (`frontend/src/app/store.js`, `frontend/src/lib/baseApi.js`)  
**Requirement Reference:** Requirement 1 ("Centralized Base API Auto-Refetch & Focus Rehydration")

---

## 1. Goal & Objectives
Permanently eliminate stale data when users switch browser tabs or recover internet connectivity.
- **Redux Store:** Activate RTK Query's global listeners via `setupListeners(store.dispatch)` in `store.js`.
- **Base API:** Enable `refetchOnFocus: true` and `refetchOnReconnect: true` at the root `createApi` configuration in `baseApi.js`.
- **Cache Retention:** Configure balanced `keepUnusedDataFor: 300` (5 minutes) so that recently visited screens remain responsive without holding dead memory indefinitely.

---

## 2. File-Level Changes

### 1. `frontend/src/app/store.js`
- Import `setupListeners` from `@reduxjs/toolkit/query`:
  ```javascript
  import { setupListeners } from '@reduxjs/toolkit/query';
  ```
- Wire `setupListeners(store.dispatch);` right after `configureStore(...)`.
- Ensure listeners are safely bound in both browser and headless/test environments.

### 2. `frontend/src/lib/baseApi.js`
- In `createApi({ ... })`:
  - Add `refetchOnFocus: true` — automatically refetches active queries when user returns to the HRM tab.
  - Add `refetchOnReconnect: true` — automatically refetches active queries when browser comes back online after network drop.
  - Set `keepUnusedDataFor: 300` — caches unused endpoint data for 5 minutes before garbage collection.
- Document the networking behavior with clear inline comments explaining how this eliminates the need for manual `F5` refreshes.

---

## 3. Verification Criteria
1. When navigating away from the HRM browser tab to another application/tab and returning, all active queries on screen re-trigger a silent background fetch.
2. Toggling browser offline/online mode in DevTools Network tab immediately triggers revalidation upon reconnect.
3. No duplicate network storm: Multiple components reading the same query share the single in-flight deduplicated request.
4. Linter passes with 0 errors; Vite production build passes cleanly.
