# Plan 41-05: Optimistic UI Updates & Error Rollbacks for High-Frequency Actions

**Phase:** Phase 41: Software-Wide Real-Time Data Synchronization, RTK Query Cache Invalidation & Automatic Refresh System  
**Plan ID:** 41-05  
**Target:** High-Frequency Self-Service Endpoints (`attendanceApi.js`, `notificationsApi.js`, `feedbackApi.js`)  
**Requirement Reference:** Requirement 3 ("Optimistic Cache Updates for High-Frequency Self-Service Actions")

---

## 1. Goal & Objectives
Eliminate perceived network latency for frequent user interactions. Instead of waiting 300ms–800ms for a round-trip HTTP response, the UI immediately updates locally upon clicking, with an automated rollback if the backend rejects the request.
- Implement `onQueryStarted` optimistic cache patching for:
  - Marking single or all notifications as read (`markAsRead`, `markAllAsRead`).
  - Attendance check-in / check-out button state toggle.
  - Quick status toggles (e.g. employee active/inactive toggle, bookmarking).
- Ensure error handlers call `patchResult.undo()` cleanly if the request fails, reverting the UI to its true database state.

---

## 2. File-Level Changes

### 1. `frontend/src/features/notifications/notificationsApi.js`
- In `markNotificationAsRead`:
  - Use `onQueryStarted(id, { dispatch, queryFulfilled })` to optimistically decrement `unreadCount` in cache and set `read: true` on the item.
  - Catch errors and call `patchResult.undo()`.
- In `markAllNotificationsAsRead`:
  - Optimistically set `unreadCount: 0` and mark all items in cache as `read: true`.

### 2. `frontend/src/features/attendance/attendanceApi.js`
- In `checkIn` and `checkOut`:
  - Optimistically reflect punch status on `getMyTodayAttendance` query.
  - On error, rollback cleanly and display error toast.

---

## 3. Verification Criteria
1. Clicking "Mark as Read" on a notification immediately clears the unread badge with 0ms perceived lag.
2. If backend returns an error (or network is cut during punch), UI smoothly reverts back to previous state without crashing.
3. Linter passes with 0 errors; Vite production build passes cleanly.
