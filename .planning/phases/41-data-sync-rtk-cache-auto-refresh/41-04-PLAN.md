# Plan 41-04: Smart Background Polling for Mission-Critical Operational Consoles

**Phase:** Phase 41: Software-Wide Real-Time Data Synchronization, RTK Query Cache Invalidation & Automatic Refresh System  
**Plan ID:** 41-04  
**Target:** Live Operational Consoles (`TeamAttendancePage.jsx`, `DashboardPage.jsx`, `NotificationsPage.jsx`, `CandidatePipelinePage.jsx`)  
**Requirement Reference:** Requirement 4 ("Targeted Smart Background Polling for Mission-Critical Consoles")

---

## 1. Goal & Objectives
Provide an ultra-reliable safety net for mission-critical operations screens. Even in environments where WebSockets are delayed, throttled by proxies, or blocked by corporate firewalls, operational screens must stay 100% synchronized via intelligent background polling.
- Introduce visibility-aware polling intervals (e.g. 15s to 30s) on key real-time views:
  - `TeamAttendancePage.jsx` (Live floor attendance, late arrivals, on-duty staff)
  - `DashboardPage.jsx` (Executive KPIs, headcount, live attendance rates)
  - `NotificationsPage.jsx` & Topbar notification counter
  - `CandidatePipelinePage.jsx` (Live ATS candidate transitions)
- Dynamically pause polling when `document.visibilityState === 'hidden'` or when tab is blurred, completely eliminating wasted network requests when the user is not looking at the screen.

---

## 2. File-Level Changes

### 1. `frontend/src/hooks/useSmartPolling.js` (New Utility Hook)
- Provides a responsive polling interval that returns `activeInterval` when the tab is visible and `0` (paused) when hidden:
  ```javascript
  export const useSmartPolling = (intervalMs = 20000) => {
    const [isVisible, setIsVisible] = useState(
      typeof document !== 'undefined' ? document.visibilityState === 'visible' : true
    );
    useEffect(() => {
      const handleVisibilityChange = () => {
        setIsVisible(document.visibilityState === 'visible');
      };
      document.addEventListener('visibilitychange', handleVisibilityChange);
      return () => document.removeEventListener('visibilitychange', handleVisibilityChange);
    }, []);
    return isVisible ? intervalMs : 0;
  };
  ```

### 2. Operational Pages Updates
- `TeamAttendancePage.jsx`: Use `pollingInterval: useSmartPolling(15000)` in `useGetTeamAttendanceQuery`.
- `DashboardPage.jsx`: Use `pollingInterval: useSmartPolling(30000)` for KPI queries.
- `NotificationsPage.jsx` / `NotificationBell.jsx`: Use `pollingInterval: useSmartPolling(20000)` as fallback for unread badge counts.

---

## 3. Verification Criteria
1. While on the Team Attendance page, staff check-ins update automatically within 15 seconds even if WebSockets are disabled.
2. Switching to another browser tab pauses the polling timer; zero outgoing HTTP requests occur while hidden.
3. Returning to the tab immediately resumes polling and executes an instant re-fetch.
4. Linter passes with 0 errors; Vite production build passes cleanly.
