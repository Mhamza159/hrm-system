# Plan 35-01: Backend Core Schema Extension, Zod Validators, SettingService Cache Hardening & Cross-Module Consumer Alignment

**Phase**: 35 — Settings Module Complete Overhaul  
**Status**: Planned  
**Layer**: Backend Core Services, Models & Validators  
**Estimated Complexity**: Moderate  

---

## 1. Goal
Harden the core settings engine in `backend/src/modules/settings/`:
1. Register official Zod validation schemas for `qrAttendance` and `faceAttendance` in `SETTING_SCHEMAS`.
2. Extend `leavePolicySchema` to support rich structured `approvalChains` (multi-tier routing rules, roles, and day thresholds).
3. Extend `geoFencesSchema` to support branch metadata (`branchCode`, `address`, `isActive`, `isHeadquarters`).
4. Update `DEFAULT_SETTINGS` in `setting.service.js` with canonical defaults for all 10 sections including `qrAttendance` and `faceAttendance`.
5. Align cross-module consumers (e.g. `attendance.service.js`) to use `SettingService.getSetting()` instead of raw `Setting.findOne()`.

---

## 2. Requirements & Scope

1. **Validators (`backend/src/modules/settings/setting.validation.js`)**:
   - `qrAttendanceSchema`: `{ isEnabled: z.boolean().default(true), rotationSeconds: z.number().int().min(10).max(120).default(30) }`
   - `faceAttendanceSchema`: `{ isEnabled: z.boolean().default(true), matchThreshold: z.number().min(0.2).max(0.8).default(0.50), requireLiveness: z.boolean().default(true) }`
   - `approvalChainTierSchema`: `{ tier: z.number().int().min(1), role: z.string(), minDaysThreshold: z.number().int().min(0).default(0), description: z.string().optional() }`
   - Extend `leavePolicySchema` to include optional `approvalChains: z.array(approvalChainTierSchema).optional()` while maintaining full backward compatibility with `approvalChainLevels`.
   - Update `geoFenceItemSchema` to include `id: z.string().optional()`, `branchCode: z.string().optional()`, `address: z.string().optional()`, `isHeadquarters: z.boolean().default(false)`.

2. **Default Configurations (`backend/src/modules/settings/setting.service.js`)**:
   - Add canonical `qrAttendance` default.
   - Add canonical `faceAttendance` default.
   - Add default `approvalChains` configuration in `leavePolicy`.
   - Add helper methods for reading settings safely with type fallbacks.

3. **Consumer Alignment**:
   - Replace raw `Setting.findOne({ key: 'qrAttendance' })` and `Setting.findOne({ key: 'faceAttendance' })` in `attendance.service.js` with `SettingService.getSetting(...)` to take advantage of the in-memory cache bus.

---

## 3. Implementation Steps

1. Edit `backend/src/modules/settings/setting.validation.js`:
   - Define `qrAttendanceSchema`, `faceAttendanceSchema`, `approvalChainTierSchema`.
   - Register them in `SETTING_SCHEMAS`.
2. Edit `backend/src/modules/settings/setting.service.js`:
   - Update `DEFAULT_SETTINGS` with `qrAttendance`, `faceAttendance`, and rich `leavePolicy.approvalChains`.
3. Edit `backend/src/modules/attendance/attendance.service.js`:
   - Replace raw `Setting.findOne` calls for `qrAttendance` and `faceAttendance` with `SettingService.getSetting(...)`.
4. Run existing test suite to ensure zero regressions across attendance and settings.
