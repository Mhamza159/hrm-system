# Plan 35-04: Leave Policy Overhaul, Accrual Governance & Interactive Approval Chains Builder

**Phase**: 35 — Settings Module Complete Overhaul  
**Status**: Planned  
**Layer**: Fullstack (Backend Service & Algorithm + Frontend Component)  
**Estimated Complexity**: High  

---

## 1. Goal
Overhaul Section 4 (Leave Policy) and introduce an enterprise-grade **Interactive Approval Chains Builder**:
1. Leave Governance: Fiscal cycle (July-June vs. January-December), maximum annual carry-forward limit, encashment eligibility toggle, sandwich rule enforcement, and probation period leave restrictions.
2. **Interactive Approval Chains Builder**:
   - Visual step-by-step workflow designer showing the exact escalation path for employee leave requests.
   - Tier 1: Direct Line Manager / Department Manager.
   - Tier 2: Department Head / HR Operations Manager.
   - Tier 3: Super Admin / Executive Approval for extended leaves (requests exceeding configurable days threshold, e.g. > 5 days).
   - Delegation & auto-forwarding policies for absent managers.
3. Align `backend/src/modules/leaves/leave.service.js` `buildApprovalChain()` to consume the configured dynamic chain when present, with seamless fallback to `approvalChainLevels`.

---

## 2. Requirements & Scope

1. **Backend Integration (`backend/src/modules/leaves/leave.service.js`)**:
   - Enhance `buildApprovalChain(employee, netDays)`:
     - Check `leavePolicy.approvalChains`. If configured with custom tiers, evaluate each tier based on `minDaysThreshold` and role assignment.
     - Fallback seamlessly to the standard dual/tri-level default if no custom tiers are defined.
   - Ensure leave cancellation and approval progression remain 100% backward compatible.

2. **Frontend Component (`frontend/src/features/settings/components/LeavePolicyForm.jsx`)**:
   - Card 1: Fiscal Year & Accrual Rules (Fiscal Cycle dropdown with Pakistan corporate July-June explanation, Carry-forward quota input, Encashment toggle, Probation policy).
   - Card 2: Sandwich Rule & Public Holiday Concurrency (Visual diagram showing how weekends between leaves are treated when sandwich rule is active vs inactive).
   - Card 3: Interactive Approval Chains Builder:
     - Visual vertical stepper / sequence nodes with drag or add/remove step capability.
     - Step attributes: Approver Role (Department Manager, HR Manager, Super Admin), Days Threshold (`Applies to all leaves` vs `Only for leaves > N days`), and mandatory comment requirements.
     - Validation ensuring Tier 1 is always present and steps are ordered logically.

---

## 3. Implementation Steps

1. Update `backend/src/modules/leaves/leave.service.js`:
   - Enhance `buildApprovalChain` to inspect `leavePolicy.approvalChains` array when present.
2. Redesign `frontend/src/features/settings/components/LeavePolicyForm.jsx`:
   - Implement the visual Approval Chains Builder with step nodes, role badges, and threshold controls.
   - Implement the sandwich rule explanation diagram.
   - Connect save action to `PATCH /api/v1/settings/leavePolicy`.
3. Verify leave application creation with custom approval chain settings.

- Playwright browser test verifying the Approval Chain Builder UI, adding a tier, toggling sandwich rule, and saving successfully.
