## 2. Step-by-Step Implementation

### Step 1: Implement `getShiftStats` in `department.service.js`
- Compute 7 essential live KPI metrics using high-efficiency MongoDB aggregation:
  1. `total`: Total non-deleted shifts (`isDeleted: false`).
  2. `active`: Active non-archived shifts (`isDeleted: false, isActive: true, isArchived: { $ne: true }`).
  3. `archived`: Archived shifts (`isDeleted: false, isArchived: true`).
  4. `assignedStaff`: Total active employees assigned to any non-deleted shift (`Employee.countDocuments({ shiftId: { $ne: null }, isDeleted: false })`).
  5. `staffedShifts`: Shifts with $\ge 1$ assigned employee.
  6. `emptyShifts`: Active shifts with 0 assigned employees.
  7. `nightShifts`: Active shifts flagged with `isCrossMidnight: true` or `type: 'night'`.
  8. `totalEmployees`: Total non-deleted employees in the organization to compute unassigned employees (`totalEmployees - assignedStaff`).

### Step 2: Implement `getShiftAnalytics` in `department.service.js`
- Return detailed breakdown collections for visual chart rendering:
  1. `typeDistribution`:
     - Group active shifts by `type` (`fixed`, `flexible`, `night`).
     - Calculate shift count and total assigned staff per type.
  2. `shiftHeadcounts`:
     - Top shifts sorted by headcount descending: `{ _id, name, code, type, startTime, endTime, isCrossMidnight, headcount, capacity }`.
  3. `departmentBreakdown`:
     - Cross-tabulation of shifts and employees across departments.
  4. `dayNightRatio`:
     - Day shifts (`isCrossMidnight: false` and `type != 'night'`) vs Night/Overnight shifts (`isCrossMidnight: true` or `type == 'night'`).

### Step 3: Implement `getShiftEmployees` & Enriched `getShiftById`
- **`getShiftEmployees(id, { page = 1, limit = 10, search = '' })`**:
  - Verify shift exists.
  - Query employees: `{ shiftId: id, isDeleted: false }`.
  - Apply search on `name`, `employeeCode`, `email`.
  - Populate `departmentId` (`name code`) and `designationId` (`title grade`).
  - Return paginated roster with `{ employees, total, page, limit, totalPages }`.
- **`getShiftById(id)`**:
  - Enriched with populated `departmentId`, `createdBy`, `archivedBy`.
  - Include computed `headcount`, `utilizationPercentage` (if capacity > 0), and timing metadata.

### Step 4: Implement `assignEmployeesToShift(shiftId, { employeeIds, action }, actor)`
- Validate `shiftId` exists, is not deleted, and is not archived.
- Actions supported:
  - `'set'`: Overwrite assignments to only these employees.
  - `'add'`: Add employee IDs to this shift without affecting existing ones.
  - `'remove'`: Clear `shiftId` for specified employee IDs.
- Enforce capacity ceiling: if `shift.capacity > 0`, verify that new total headcount will not exceed `shift.capacity`.
- Atomic update using `Employee.updateMany`.
- Record comprehensive audit log: action `shift.assign_employees`.

### Step 5: Register Routes in `shift.routes.js`
- `GET /stats` -> `departmentController.getShiftStats` (`org.view`)
- `GET /analytics` -> `departmentController.getShiftAnalytics` (`org.view`)
- `GET /:id/employees` -> `departmentController.getShiftEmployees` (`org.view`)
- `POST /:id/assign` -> `departmentController.assignEmployeesToShift` (`org.manage`, validated)
- Mount `/stats`, `/analytics`, `/archived` BEFORE `/:id`.
