# Plan 36-04: Backend Employee ID Card REST API, Verifiable Payload & RBAC/PBAC Scoped Authorization

## Objective
Implement dedicated REST endpoints (`GET /api/v1/employees/:id/id-card` and `GET /api/v1/employees/me/id-card`) in `backend/src/modules/employees/` to compile live employee coordinates with the latest company branding and `idCardConfig`. Enforce strict PBAC/RBAC authorization, generate verifiable digital signatures, and record audit logs on card generation.

---

## Technical Context
- **Files Touched**:
  - `backend/src/modules/employees/employee.controller.js`
  - `backend/src/modules/employees/employee.service.js`
  - `backend/src/modules/employees/employee.routes.js`
- **Dependencies**: Mongoose `Employee` model, `SettingService.getSetting('company')`, CASL / `checkPermission` middleware, `AuditLogService`.

---

## Detailed Implementation Steps

1. **Implement `getEmployeeIdCardData` in `employee.service.js`**:
   - Retrieve target `Employee` record by ID, populate `departmentId` (name) and `designationId` (title).
   - If not found or soft-deleted (`isDeleted: true`), throw `ApiError(404, 'Employee record not found')`.
   - Retrieve current corporate settings via `SettingService.getSetting('company')`.
   - Merge employee coordinates:
     - `employee`: `{ id, employeeCode, name, email, phone, bloodGroup, emergencyContact, department, designation, joiningDate, avatar, employmentStatus }`.
     - `company`: `{ name, legalName, address, phone, email, website, logoUrl, timezone }`.
     - `idCardConfig`: Configured layout, theme, toggles, validity, disclaimer.
   - Calculate `issueDate` (`employee.joiningDate || employee.createdAt`) and `validUntil` (`issueDate + validityYears`).
   - Generate `verificationToken` / QR code payload:
     - Encodes verifiable JSON: `{ code: employee.employeeCode, name: employee.name, dept: department.name, validUntil, signature: hmac(employee._id) }`.

2. **PBAC Scoping & Authorization**:
   - `GET /employees/me/id-card`: Authenticated employee fetches their own card (`userId === req.user._id`).
   - `GET /employees/:id/id-card`:
     - Super Admin / HR Manager: Full access.
     - Department Manager: Scoped to members of their assigned department.
     - Regular Employee: Restricted to their own employee ID; attempts to query other employees throw `ApiError(403, 'Forbidden: Cannot access other employees ID card')`.

3. **Register Endpoints in `employee.routes.js`**:
   - `router.get('/me/id-card', authenticate, employeeController.getMyIdCard);`
   - `router.get('/:id/id-card', authenticate, checkPermission('employee.view', 'own'), employeeController.getEmployeeIdCard);`

4. **Audit Logging**:
   - Record `AuditLogService.logAction` with action `EMPLOYEE_ID_CARD_GENERATED`, target employee ID, and requesting actor.

---

## Verification Criteria
- [ ] `GET /api/v1/employees/me/id-card` returns 200 with full card payload for the logged-in user.
- [ ] `GET /api/v1/employees/:id/id-card` allows Super Admin and HR to access any active employee's card.
- [ ] Unauthorized cross-employee requests return 403 Forbidden.
- [ ] Soft-deleted or non-existent employee IDs return 404 Not Found.
