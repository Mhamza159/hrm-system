# Plan 23-05: End-to-End Testing, Vitest Integration Suite & Verification Gate

## Goal
Build a comprehensive automated integration test suite (`backend/tests/notifications.e2e.test.js`) verifying multi-channel notification dispatch, module-wise aggregation, priority handling, archiving lifecycle, and PBAC security boundaries across all 4 system roles (Super Admin, HR Manager, Department Manager, Employee). Enforce 0 Oxlint warnings and a clean Vite production build.

## Proposed Changes

### 1. `backend/tests/notifications.e2e.test.js`
- Test cases to implement:
  1. **Schema & Dispatch Verification**:
     - `notify()` creates notification documents with explicit `module` and `priority`.
     - Validates fallback defaults (`module: 'system'`, `priority: 'normal'`).
  2. **Centralized Service & Aliasing**:
     - Aliased types (e.g. `leave` -> `leaves`, `asset` -> `assets`, `loan` -> `loans`) normalize accurately.
  3. **Module Unread Counts Aggregation (`GET /api/v1/notifications/module-counts`)**:
     - Accurately counts unread notifications grouped by `module` and `link` route prefix.
     - Ignores read notifications and archived notifications from unread counts.
  4. **Read / Unread Lifecycle**:
     - Marking single notification as read (`PATCH /:id/read`) updates `isRead: true` and `readAt`.
     - "Mark all as read" (`PATCH /read-all`) updates all active notifications for the actor.
  5. **Archive & Restore Lifecycle**:
     - `PATCH /:id/archive` moves notification to archive (`isArchived: true`).
     - Querying active notifications (`isArchived: false`) excludes archived items.
     - `PATCH /:id/unarchive` restores notification to active feed.
     - `PATCH /archive-all` archives all read notifications.
  6. **PBAC & Confidentiality Enforcement**:
     - Grievance notifications: Only delivered to authorized committee/HR members.
     - Attrition risk alerts: Only delivered to SuperAdmin / HR.
     - User cannot read or mutate notifications belonging to another user (`403 Forbidden` / `404 Not Found`).
  7. **Multi-Recipient Bulk Dispatch**:
     - Sending notification to array of user IDs inserts distinct documents per recipient.
  8. **Pagination & Filtering**:
     - Filtering by `module` and `priority` returns strictly matching subset.
     - Pagination (`page`, `limit`) preserves sort order (`createdAt: -1`).
  9. **Socket.io Event Emission**:
     - Confirms `emitToUser` is invoked with correct room `user:${id}` and enriched payload.
  10. **TTL & Cleanup Safety**:
     - Confirms TTL index definition on `createdAt`.
