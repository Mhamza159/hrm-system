# Plan 23-01: Backend Notifications Architecture, Schema Expansion & Module Aggregation APIs

## Goal
Upgrade the notification schema, validation, service, controller, and routes to support explicit module attribution, priority tiers (`low`, `normal`, `high`, `urgent`), archive lifecycle (`archive` and `unarchive`), and high-performance module unread count aggregation (`GET /api/v1/notifications/module-counts`).

## Proposed Changes

### 1. `backend/src/models/notification.model.js`
- Add `module` field:
  - String enum with values: `['system', 'recruitment', 'employees', 'attendance', 'leaves', 'payroll', 'loans', 'expenses', 'assets', 'projects', 'performance', 'lifecycle', 'policies', 'announcements', 'rewards', 'feedback', 'chat', 'attrition', 'reports', 'settings']`.
  - Default: `'system'`.
  - Indexed for fast module-wise aggregation.
- Add `priority` field:
  - String enum: `['low', 'normal', 'high', 'urgent']`.
  - Default: `'normal'`.
- Add `isArchived` & `archivedAt` fields:
  - `isArchived: { type: Boolean, default: false, index: true }`.
  - `archivedAt: { type: Date, default: null }`.
- Compound Indexes:
  - `{ userId: 1, isArchived: 1, isRead: 1, createdAt: -1 }`.
  - `{ userId: 1, isArchived: 1, module: 1, isRead: 1 }`.
  - Maintain TTL index on `createdAt`.

### 2. `backend/src/services/notify.service.js`
- Enhance `notify(userIds, payload)`:
  - Support `module` with alias normalization (e.g. `leave` -> `leaves`, `asset` -> `assets`, `timesheet` -> `projects`, `loan` -> `loans`, `expense` -> `expenses`, `onboarding` -> `lifecycle`, `policy` -> `policies`, `announcement` -> `announcements`, `appraisal` -> `performance`).
  - Support `priority` (`urgent`, `high`, `normal`, `low`). Default to `'normal'`.
  - Save `module` and `priority` in MongoDB `Notification.insertMany()`.
  - Include `module`, `priority`, `isArchived` in Socket.io `notification:new` payload.
- Implement `getModuleUnreadCounts(userId)`:
  - MongoDB aggregation pipeline on `{ userId, isArchived: false, isRead: false }`.
  - Group by `module` and by `link` prefix.
  - Return formatted summary:
    ```json
    {
      "totalUnread": 5,
      "byModule": {
        "leaves": 2,
        "attendance": 1,
        "announcements": 2
      },
      "byRoute": {
        "/leaves/approvals": 2,
        "/attendance/team": 1,
        "/announcements": 2
      }
    }
    ```

### 3. `backend/src/modules/notifications/`
- **Validation (`notification.validation.js`)**:
  - Add query validation for `module`, `priority`, `isArchived`, `page`, `limit`.
- **Service (`notification.service.js`)**:
  - Update `getNotifications(userId, query)` to support filtering by `module`, `priority`, and `isArchived` (defaults to `false`).
  - Add `archiveNotification(notificationId, userId)`.
  - Add `unarchiveNotification(notificationId, userId)`.
  - Add `archiveAllNotifications(userId)`.
  - Add `getModuleNotificationCounts(userId)`.
- **Controller (`notification.controller.js`)**:
  - Add `getModuleCounts` handler invoking `getModuleNotificationCounts`.
  - Add `archiveNotification` handler (`PATCH /:id/archive`).
  - Add `unarchiveNotification` handler (`PATCH /:id/unarchive`).
  - Add `archiveAll` handler (`PATCH /archive-all`).
- **Routes (`notification.routes.js`)**:
  - `GET /api/v1/notifications/module-counts` -> `getModuleCounts`.
  - `PATCH /api/v1/notifications/:id/archive` -> `archiveNotification`.
  - `PATCH /api/v1/notifications/:id/unarchive` -> `unarchiveNotification`.
  - `PATCH /api/v1/notifications/archive-all` -> `archiveAll`.

## Verification Criteria
- [ ] Schema allows creating notifications with `module`, `priority`, and archival fields.
- [ ] Centralized `notify()` stores and broadcasts enriched notification objects.
- [ ] `GET /api/v1/notifications/module-counts` returns accurate counts grouped by module.
- [ ] Archiving updates `isArchived: true` and removes it from active list and unread count.
