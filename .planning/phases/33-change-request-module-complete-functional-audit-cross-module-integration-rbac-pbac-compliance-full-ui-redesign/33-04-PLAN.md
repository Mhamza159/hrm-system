# Plan 33-04: Enterprise Change Request Explorer & Multi-Criteria Filter Suite

## Objective
Rebuild the Change Request listing into an enterprise-grade data explorer. Implement a full-featured DataTable with rich employee identity credentials, category badges, inline current vs requested previews, submission date, reviewer attribution, and status pills. Build a sticky filter toolbar with debounced multi-field search, category dropdown, status chips, department filtering, and pagination.

## Tasks
1. **Filter & Search Toolbar Component (`ChangeRequestFilterBar.jsx`)**:
   - Debounced search input (queries employee name, employee code, request ID, and reason).
   - Category filter dropdown (`All Categories`, `Personal Info`, `Contact Details`, `Address`, `Emergency Contact`, `Bank & IBAN`, `Department`, `Designation`, `Reporting Manager`).
   - Quick-filter status tabs/chips (`All`, `Pending`, `Under Review`, `Approved`, `Rejected`, `Returned`).
   - Department filter dropdown populated from active departments.
   - Priority filter (`All`, `Normal`, `High`, `Urgent`).
   - Active filter tags with one-click clear chips and a "Reset All" action.

2. **Enterprise Change Request DataTable (`ChangeRequestTable.jsx`)**:
   - **Employee Identity Cell**: Avatar / initials fallback, full name, employee code (`font-mono text-slate-500`), department badge, and designation.
   - **Category & Field Pill**: Semantic badge with Lucide icon indicating category (`User`, `Phone`, `MapPin`, `CreditCard`, `Building2`, `Briefcase`).
   - **Change Preview**: Inline concise preview showing Old Value $\rightarrow$ New Value with visual delta highlight.
   - **Priority Badge**: Subtle pill indicating `Normal`, `High`, or `Urgent`.
   - **Submission & Age**: Formatted submission date with relative age tooltip (`2 days ago`).
   - **Reviewer Attribution**: Assigned reviewer or decided-by user identity.
   - **Status Pill**: Semantic color-coded pill matching `docs/UI-REFERENCE.md` (`pending`, `under_review`, `approved`, `rejected`, `returned`).
   - **Action Menu**: Quick actions (Inspect Details, Quick Approve, Quick Reject, Return for Correction) governed strictly by permissions.

3. **Empty States, Pagination & Loading Polish**:
   - Tailored empty states for "No requests found" vs "No requests match active filters".
   - Shimmer table skeletons for loading states.
   - Pagination footer with page size selector (10, 25, 50, 100) and record range summary (`Showing 1-10 of 48 requests`).

## Verification Criteria
- Table displays complete employee identity without truncation or unformatted IDs.
- Debounced search filters records smoothly without redundant network requests.
- Filter chips accurately reflect and clear individual active filters.
- Responsive layout scrolls horizontally on mobile/tablet viewports without breaking container bounds.
