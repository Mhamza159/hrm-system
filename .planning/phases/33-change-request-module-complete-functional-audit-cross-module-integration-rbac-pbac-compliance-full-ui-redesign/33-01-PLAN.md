# Plan 33-01: Change Request Data Model, Lifecycle Engine & Cross-Module Master Synchronization

## Objective
Overhaul the Change Request data model and core service layer into a robust, transactional synchronization engine. Enrich `ProfileChangeRequest` (or alias `ChangeRequest`) Mongoose schema with categories, baseline snapshots (`oldValue`), file attachments, priority, reviewer attribution, decision reasoning, and an immutable status timeline. Implement atomic approval synchronization that correctly updates `Employee` master records (Personal, Contact, Address, Emergency Contact, Bank details with AES-256-GCM encryption, Department, Designation, Reporting Manager) and user records (`User.name`), while recording promotion/transfer events in `EmployeeHistory`.

## Tasks
1. **Schema Enhancement (`backend/src/models/profileChangeRequest.model.js`)**:
   - Add `category`: enum `['personal', 'contact', 'address', 'emergency_contact', 'bank_details', 'department', 'designation', 'reporting_manager']`, required, indexed.
   - Add `field`: String (specific attribute or composite group).
   - Add `oldValue`: Mixed (baseline snapshot of target field values captured at submission time).
   - Add `requestedValue`: Mixed (new proposed data).
   - Add `priority`: enum `['normal', 'high', 'urgent']`, default `'normal'`.
   - Add `status`: enum `['pending', 'under_review', 'approved', 'rejected', 'returned', 'cancelled']`, default `'pending'`, indexed.
   - Add `attachments`: array of `{ name: String, url: String, fileType: String, size: Number, uploadedAt: Date }`.
   - Add `assignedTo`: ObjectId ref `'User'`, default `null`, indexed.
   - Add `decisionReason`: String (for rejection notes or return instructions).
   - Add `timeline`: array of `{ action: String, actor: ObjectId ref 'User', actorName: String, actorRole: String, note: String, timestamp: Date }`.
   - Add `isDeleted`: Boolean, default `false`, indexed.
   - Add compound indexes: `{ status: 1, createdAt: -1 }`, `{ employeeId: 1, status: 1 }`, `{ category: 1, status: 1 }`.

2. **Cross-Module Master Synchronization Service (`backend/src/modules/employees/employee.service.js`)**:
   - Enhance `decideChangeRequest` to support complete multi-category application upon `approved`:
     - **`personal`**: Mutate `fullName`, `gender`, `dob`, `maritalStatus`, `bloodGroup` on `Employee`. If `fullName` changed, synchronize `User.name` in the authentication collection.
     - **`contact`**: Mutate `phone`, `personalEmail` on `Employee`.
     - **`address`**: Safely merge updated `street`, `city`, `state`, `postalCode`, `country` into `Employee.address`.
     - **`emergency_contact`**: Update `name`, `relationship`, `phone` in `Employee.emergencyContact`.
     - **`bank_details`**: Encrypt `iban` with AES-256-GCM via `encrypt()`, update `bankName`, `accountTitle`, `accountNumber`, `iban` in `Employee.bankDetails`.
     - **`department`**: Validate target department exists and is active. Mutate `Employee.departmentId`. Create record in `EmployeeHistory` tracking transfer event.
     - **`designation`**: Validate target designation exists and is active. Mutate `Employee.designationId`. Create record in `EmployeeHistory` tracking promotion/redesignation.
     - **`reporting_manager`**: Validate target manager is active, not self, and does not create circular reporting dependency. Mutate `Employee.reportingManagerId`.
   - Implement `returnChangeRequest(id, { notes }, actor)`: Transitions status to `returned`, appends to timeline, stores `decisionReason`, and notifies employee.
   - Implement `cancelChangeRequest(id, { reason }, actor)`: Allows employee to withdraw own pending request, transitions to `cancelled`, appends to timeline.

3. **Baseline Snapshot Capture on Submission**:
   - In `submitChangeRequest`, dynamically query the current `Employee` record and extract the current values for `category`/`field` into `oldValue`.
   - Push initial `submitted` entry to `timeline` with requesting user identity and timestamp.

## Verification Criteria
- All 8 categories capture accurate baseline snapshots (`oldValue`) upon request creation.
- Approval of department and designation requests updates the employee and appends an `EmployeeHistory` record.
- Sensitive banking IBAN is encrypted at rest using AES-256-GCM.
- Rejection and Return actions leave the original employee record untouched.
- Circular reporting manager relationships are strictly blocked with HTTP 400.
