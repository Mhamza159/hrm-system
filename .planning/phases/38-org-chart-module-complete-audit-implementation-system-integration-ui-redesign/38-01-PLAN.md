# Plan 38-01: Backend API & Hierarchy Engine Hardening

## Objective
Harden the organizational hierarchy engine in `backend/src/modules/departments/department.service.js` and controller in `department.controller.js`. Eliminate hardcoded role/designation strings (`EMP-000`, `Chief Executive Officer`, `Executive Management`), add multi-root support, implement robust DAG cycle and self-reporting prevention, support server-side query filters (`departmentId`, `viewMode`, `employeeId`, `maxDepth`, `status`), compute enterprise hierarchy statistics, and enforce PBAC field-level masking for sensitive contact coordinates.

---

## Technical Context
- **Files Touched**:
  - `backend/src/modules/departments/department.service.js`
  - `backend/src/modules/departments/department.controller.js`
  - `backend/src/modules/departments/department.routes.js`
  - `backend/src/modules/departments/department.validation.js` (Add schema for org chart query params)
- **Dependencies**: Mongoose `Employee`, `Department`, `Designation`, CASL / PBAC scopes (`req.permissionScope`).

---

## Detailed Implementation Steps

1. **Query Validation Schema (`department.validation.js`)**:
   - Add `getOrgChartQuerySchema`:
     ```javascript
     export const getOrgChartQuerySchema = z.object({
       departmentId: z.string().optional(),
       viewMode: z.enum(['company', 'department', 'team', 'employee']).default('company'),
       employeeId: z.string().optional(),
       maxDepth: z.coerce.number().int().min(1).max(10).optional(),
       status: z.enum(['active', 'all']).default('active'),
       search: z.string().optional()
     });
     ```

2. **Controller Hardening (`department.controller.js`)**:
   - In `getOrgChart`:
     - Parse and validate `req.query` using `getOrgChartQuerySchema`.
     - Evaluate effective PBAC scope: `'all'`, `'department'`, `'team'`, `'own'`.
     - Check if requester has `employee.viewSensitive` or `employee.manage` to determine if email/phone can be displayed unmasked.
     - Pass options to `departmentService.getOrgChart`:
       ```javascript
       const options = {
         departmentId: req.query.departmentId,
         viewMode: req.query.viewMode,
         employeeId: req.query.employeeId,
         maxDepth: req.query.maxDepth ? parseInt(req.query.maxDepth, 10) : undefined,
         status: req.query.status || 'active',
         search: req.query.search,
         canViewSensitive: hasPermission(req.user, 'employee.viewSensitive') || isSuperAdmin
       };
       const chartData = await departmentService.getOrgChart(req.user?._id, scope, req.user, options);
       ```

3. **Service Overhaul (`department.service.js`)**:
   - **Database Query**:
     - Query `Employee.find(query)` with populated `departmentId` and `designationId`.
     - Filter out terminated/resigned employees if `options.status === 'active'`.
   - **Dynamic Designation & Department Resolution**:
     - Remove hardcoded `EMP-000` / `Chief Executive Officer` checks.
     - Use actual `emp.designationId?.title || 'Unassigned Designation'` and `emp.departmentId?.name || 'Unassigned Department'`.
   - **Cycle & Self-Reporting Prevention**:
     - Sanitize `emp.managerId`: If `emp.managerId.toString() === emp._id.toString()`, reset `emp.managerId = null`.
     - Track visited node IDs using a `Set` during tree generation to break any circular reporting chains (e.g. A reports to B, B reports to A).
   - **Dangling / Inactive Manager Reparenting**:
     - If an employee has a `managerId` pointing to an employee not in the active dataset, check if that manager has a superior; if so, reparent to the superior (skip-level), otherwise treat as a secondary root so subtrees are never lost.
   - **Sensitive Contact PBAC Masking**:
     - If `!options.canViewSensitive`, mask personal phone (`+92 3** *******`) and email (`e***@***.com`) unless it is the user's own card (`isMe`).
   - **Hierarchy Statistics Calculation**:
     - Compute and return:
       ```javascript
       stats: {
         totalNodes,
         departmentsCount,
         managersCount,
         maxDepth,
         spanOfControlAvg,
         unassignedCount
       }
       ```
   - **View Modes Support**:
     - `viewMode === 'team'`: Root tree at the specified manager or requesting user's employee record.
     - `viewMode === 'department'`: Group or filter tree by department heads and their department rosters.
     - `viewMode === 'employee'`: Return employee focal subtree (manager, employee, peers, and direct reports).

## Verification Criteria
- [ ] No hardcoded designations (`CEO`, `Executive Management`, `EMP-000`).
- [ ] Circular reporting loops pruned cleanly without stack overflows.
- [ ] Subtrees with deleted or inactive managers retained safely without disappearing.
- [ ] Sensitive contacts masked for unauthorized callers.
- [ ] Rich summary statistics (`stats`) returned in payload.
